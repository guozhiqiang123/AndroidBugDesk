# Android Bug Desk implementation notes

- Use Rust + Tauri 2, with React/TypeScript for the renderer. The user's Tauri decision overrides the Electron recommendation in the preserved original plan.
- Target macOS arm64/x64, Windows x64, and Linux x64. Packaging runs natively through GitHub Actions.
- Read `docs/tasks.md` and `docs/acceptance.md` before continuing. Report implemented, mock-verified and real-world-verified capabilities separately.
- The user explicitly stopped sub-agent/Multica delegation in this project. The current agent directly reads, implements, builds and verifies; do not spawn or dispatch agents unless the user explicitly reauthorizes it. Read `docs/multica-collaboration.md` only for an explicitly requested Squad operation; its coordinator-only limits do not apply to ordinary work here.
- Cloud verification remains subject to the current task's authorization. Never read another app's or coordinator's PAT. Do not perform real Yunxiao writes without a user-designated acceptance scope.
- Read `docs/git-delivery-policy.md` before GitHub operations. The public remote is `guozhiqiang123/AndroidBugDesk`; normal task pushes, candidate builds and accepted PR merges follow its gates. A pending public-history review blocks source pushes. Publishing releases, force pushes and destructive operations are outside this policy.
- Keep credentials, network, ADB and file access in Rust. Do not add generic shell commands, unrestricted file-path IPC or renderer HTTP permissions.
- The settings-page project mapping is the sole source of Android package identity. When the current enabled project has no valid saved package, the new-submission page exposes only a blocking explanation and a Settings link; device actions, evidence actions, imports, preview and submission stay unavailable. New and saved drafts, Rust ADB commands, sessions, post-capture and submission must re-read that scoped mapping. Foreground inspection may update the optional Bug page but must never replace the configured package.
- The old application/device dialog and its eleven manual fields have been removed. Do not restore it or the old “at least one app/device value” gate. Hidden draft app/device fields remain for reports and compatibility; package is required and synchronized from project settings, while other values may be populated by device inspection.
- ADB path selection, device refresh and target device selection live on one row in the evidence attachments section, sharing the existing device/session state and collection guards. Do not restore a separate foreground re-read button; refreshing or selecting a device continues to run the existing automatic inspection. Device and ADB failures stay below their corresponding main-page controls. Manual attachment import remains optional once the project package gate is satisfied.
- “设备环境快照” is a direct evidence action. It creates one system-previewable UTF-8 text attachment containing timestamped, per-command results for selected product/build properties, system locale/timezone, screen size/density, concise memory/storage availability, battery, the configured package dump, font scale and app locales. Do not restore full getprop, full system/secure/global settings or connectivity/Wi-Fi/netstats to this generic snapshot; those caused broad and duplicate collection. Use only the fixed argv whitelist, preserve partial results, never infer the package from the foreground app, and recheck device/scope/package before writes. Keep this separate from the issue-type post-capture recommendations.
- Post-capture displays one latest result per evidence item. Whole-device bugreport starts selected only for ANR, where thread and system blocking context materially supports diagnosis; it remains a manual fallback for other issue types. Log dumps and live log sessions are restricted to the configured package's Android UID; never fall back to whole-device logs when UID resolution or filtering is unavailable. General logs exclude the crash buffer because the crash item owns it. CPU, window and network diagnostics retain system context that materially supports contention, display and network-path analysis, but start selected only for their mapped issue types; do not remove diagnostically useful data merely to reduce attachment size. Completed recommended items start unchecked; explicitly collecting an item again replaces that item's older generated draft attachment and the prior regular summary, including their managed files. Temporary ZIP/screenshot sources and successful raw bugreport directories must not retain a second copy. Keep manual imports and other item types. Environment-only capture adds its text attachment without a redundant summary. Show bugreport elapsed time and its usual 1–2 minute duration, retain the hard timeout, and turn abnormal worker termination into an interrupted result rather than leaving a permanent pending job.
- Participants and CC (native targets `participants` and `trackers`, including mapped aliases) start unchecked for new drafts and type changes. Do not apply first-option defaults or selection memory to them, including inside the custom select component. Preserve explicit selections in the current/saved draft and keep clearing them effective after metadata refresh.
- Keep one multi-file attachment import entry and classify evidence in Rust. On macOS, open inspected PNG/JPEG attachments explicitly with `/System/Applications/Preview.app` and ZIP reports through Quick Look so the default Archive Utility does not expand them beside managed evidence. Use the existing cross-platform default opener for other formats/platforms; do not change global file associations, restore separate format buttons or internal viewers. Preview IPC accepts draft/attachment IDs, resolves the stored file in Rust, and shows failures below its preview button. Do not restore the removed application/device dialog, its manual log/system-report actions, or its renderer handlers.
- Imported attachments are optional for every issue kind. Do not require a log, screenshot, video, or minimum file count to preview or submit. Validate any files that are present, including log coverage and paired receipts. Keep the evidence entry buttons aligned independently of the messages below each button, and omit the removed evidence explanatory paragraph. The late-capture checkbox and draft property have been removed; do not infer a late-capture flag, change the event source based on the session start time, or add this field to reports.
- Put input guidance in placeholders, including dialogs; preserve existing hints and remove duplicate orange text below controls. Empty-value instructions use hints while required validation remains in the final checks. Keep actual nonempty format errors, backend errors, collection failures and project/package mismatches at their controls; do not hide all errors to remove guidance. Empty dropdowns already show their empty state and need no duplicate API availability hint.
- Preserve unknown create/upload outcomes and remote workitem identity. An empty search is not evidence that creation failed. Do not solve retries by posting another Bug.
- Keep the original evidence ZIP immutable and store receipts separately. Unknown build fingerprints/mapping identity stay explicitly uncollected.
- When changing the draft structure, update `src/shared/domain.ts`, run `npm run schemas`, update fixtures, and verify both frontend and Rust validation. Unknown required fields must block writes.
- Match verification to the change. Business/shared-contract/Rust changes require `npm run check`, Rust formatting and Clippy, plus affected browser scenarios. Build/test-script changes require `npm run test:workflow` and the affected real workflow; documentation-only changes require formatting/diff checks. Reuse passing checks for unchanged inputs and toolchains, with source fingerprints as evidence; rerun affected checks when inputs change or a failure remains unresolved. Do not repeat the entire suite solely because time has passed or documentation changed.
- For local macOS packaging use `npm run bundle:local`, following `docs/local-workflow.md`. The output directory must not exist: keep preflight records and redirected entry logs elsewhere until the script creates it. It applies the checked-in ad hoc signing config from the first build, uses the native cache, verifies the app before making a DMG, and records logs/timings/source fingerprints. Do not use bare `npm run bundle` for this purpose or recreate temporary signing configs. The script does not install; overwrite installation requires the user's authorization.
- Browser checks share `scripts/browser-check-support.mjs`: isolated dynamic ports, automatic screenshot/HTML/error evidence, cleanup and source-change guards. Do not create temporary diagnostic copies, add fixed ports, or blindly retry an unchanged failure. Resolve the primary error using the first run's evidence.
- When CodeGraph reports stale or unindexed source, use rg/direct reads for those files immediately; do not repeat the same stale exploration or reindex without the user's request.
- During first-version development, when the user authorizes installing a new package, directly overwrite the local app. Do not inspect, save, migrate, or restore old drafts; the user explicitly accepts draft loss. Old-app/data backups and rollback preparation are optional and must not delay installation. Normally replace only the app bundle; do not deliberately erase local data unless requested. If the old app is running, bind it afresh and quit through the native UI without saving drafts, then verify termination with a read-only process check. Do not call its AX/screenshot methods after quitting: they can relaunch it. Rebind the installed application after replacement for startup verification. Keep the established signing, package-integrity, and startup checks.
- Do not mark the whole product accepted until the original plan's real media, USB, permission and installed-platform tests have passed.
- If the first post-install native binding times out while the new installed process is running, reset `cua_repl` once and bind the installed path again before repeating observation. A stale native connection does not justify rebuilding or reinstalling the package.

- Attachment cards put Preview and Remove in a vertical column on the right. Do not restore the per-file preview/upload checkbox or gate validation, packaging, or uploads on its legacy `confirmed` property. Every file listed in the draft participates; redaction replaces its source entry while preserving the immutable source file. Keep file integrity, log coverage, paired receipt integrity, and the final whole-submission preview check.

Retain cancellation, account-binding checks, and the default unchecked remember-login choice.

All nine history filters are custom multi-selects whose empty selection means no restriction; this exception applies to filters, not submission defaults. Resume from the consumed server cursor, preserve conditions, deduplicate IDs, and discard stale account/project/tab responses. Keep undocumented query classes out of the API request; match remaining conditions exactly against bounded results and distinguish an empty batch with more pages from a final empty result. Keep OAuth session refresh on the history API snapshot.
