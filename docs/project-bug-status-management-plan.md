# 项目 Bug 状态展示与流转计划

## 1. 目标

“项目 Bug”列表中的状态需要一眼可辨，并允许有权限的用户直接完成云效状态流转，减少为了修改一个状态而打开网页的操作。

本次包含：

- 状态按语义使用稳定颜色；未知的自定义状态按状态 ID 使用稳定的兜底色。
- 列表状态改为下拉控件；展开时读取该工作项自己的工作流状态，不使用多个 Bug 类型合并后的筛选状态直接写入。
- 选择新状态后写回云效，并同步当前页、详情短时缓存和已打开详情的状态。
- 写入中禁用重复操作；失败保留原状态并显示云效返回的权限、工作流或网络错误。
- 登录失效继续复用全局退出流程。

本次不增加批量状态修改，不在本地绕过云效工作流，也不把远端状态写入 SQLite。

## 2. 官方 API 依据

新版 Projex 提供完整能力：

- `GET /workitems/{id}/workflow` 返回指定工作项工作流的状态列表。
- `PUT /workitems/{id}` 以 `{"status":"状态 ID"}` 修改状态。
- 更新接口要求个人访问令牌具备“项目协作 / 工作项 / 读写”权限；无权限由云效返回 `403`。

接口依据：

- [GetWorkitemWorkflowInfo：获取工作项工作流信息](https://help.aliyun.com/zh/yunxiao/developer-reference/getworkitemworkflowinfo-get-work-item-workflow-information)
- [UpdateWorkitem：更新工作项](https://help.aliyun.com/en/yunxiao/developer-reference/updateworkitem)

工作流查询返回状态集合，但文档没有承诺所有状态之间都能任意跳转。因此客户端只提供云效返回的状态，并以更新接口的服务端校验为最终结论；不在本地猜测或伪造可达关系。

## 3. 交互设计

状态单元格使用紧凑下拉按钮：

- 当前状态始终可见，颜色同时作用于背景、边框和文字，并保持可读对比度。
- 第一次展开时显示读取状态，按工作项 ID 获取准确工作流；同一页面内再次展开复用内存结果。
- 当前状态仍在选项中，重新选择当前值不发送写请求。
- 选择新状态后立即关闭菜单并显示写入状态；写入成功在右下角提示“已更新为…”。
- 写入失败不改变列表状态；`403` 明确提示令牌缺少工作项读写权限，认证失效回到登录页。
- 状态控件保留键盘操作和无障碍名称，不使用仅靠颜色表达状态的设计。

颜色规则：

| 状态语义                   | 色调           |
| -------------------------- | -------------- |
| 待处理、待确认、新建、打开 | 蓝灰           |
| 处理中、修复中、进行中     | 蓝             |
| 待验证、待验收、测试中     | 橙             |
| 已解决、已修复、已完成     | 绿             |
| 暂不修复、拒绝、取消、挂起 | 紫             |
| 已关闭、已归档             | 灰             |
| 其他自定义状态             | 按状态 ID 固定 |

## 4. 数据与安全边界

新增两个受限 Tauri 命令：

```text
project_bug_workflow(id, projectId) -> Option[]
update_project_bug_status(id, statusId, projectId) -> Option
```

后端在读取或写入前执行以下检查：

1. 当前账号、组织和主页面项目作用域有效。
2. 工作项属于当前项目且类型为 Bug。
3. 目标状态 ID 出现在该工作项自己的工作流中。
4. 真正写入前再次核对账号和项目纪元，避免迟到操作落入已切换的工作区。
5. 写入请求不自动重试；网络响应不确定时提示用户刷新核对，避免重复流转。

工作流选项仅保存在当前 React 页面内存中。项目或账号切换会销毁组件及缓存；远端列表、状态与工作流不落本地数据库。

## 6. 验收标准

- 不同语义状态显示不同且稳定的颜色，文字在颜色之外仍明确展示状态。
- 展开某条 Bug 的状态只请求该工作项的工作流，不批量请求整页 50 条 Bug。
- 选择合法新状态只发送一次 `PUT`，成功后列表立即显示新状态。
- 重新选择当前状态不写云效；连续点击不能产生并发写入。
- 非当前项目、非 Bug、非法状态 ID、无权限和登录失效均不能形成未受控写入。
- 更新失败保留原状态，错误可见；项目或账号切换后的迟到响应不会更新新页面。
- 自动验证不执行真实云效写入；真实账号写入留给用户指定 Bug 的人工验收。
