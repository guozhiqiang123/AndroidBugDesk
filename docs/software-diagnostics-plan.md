# 开发者调试与软件证据实施计划

确认日期：2026-10-14。

## 目标

设置页新增本机级“开发者选项”，通过自渲染“开启调试”开关控制详细运行日志。开启后，新建提交页的“证据附件”显示“软件证据”按钮；用户点击后生成经过脱敏、受大小限制的客户端诊断 ZIP，并作为可预览、可移除、可上传的附件加入当前草稿。

软件证据用于定位客户端跨平台运行问题，包括 ADB 启动失败、命令超时、系统报告生成或传输停滞、设备断开、主线程无响应、网络耗时、文件写入及附件处理性能。它不代替设备日志、截图或整机系统报告，也不自动提交。

## 产品行为

- “开发者选项”卡片位于设置页底部；开关默认关闭，本机持久化，跨账号、组织和重启保持。
- 基础诊断始终启用，只记录启动、退出、panic、主线程超时和操作结果等低风险事件；开关只控制详细事件。
- 开启后立即生效，不要求重启；关闭后停止新增详细事件，已有文件按轮转策略清理。
- “软件证据”仅在开关开启时显示，不依赖 ADB 或设备在线。后台 ADB 任务仍在运行时也允许生成，以保留活动任务状态。
- 每个草稿只保留最新一份软件证据。重新生成时先持久化新附件，再删除被替换的受管目录。
- 软件证据参与现有预览、移除、提交和证据包流程。删除草稿时清理软件证据受管目录；用户导入的原文件和已经导出的证据包不受影响。

## 日志结构

基础日志和调试日志均使用 JSON Lines。每条事件包含 UTC 时间、单调时钟毫秒数、本次启动 ID、等级、区域、事件名、操作 ID、结果和允许字段。事件字段由调用方使用固定键构造，不接受请求正文、草稿内容或任意对象直接序列化。

基础事件包括：应用生命周期、panic、主线程看门狗、ADB 命令开始/结束/超时、更新/提交/附件操作阶段、日志写入失败和丢弃计数。

首版详细事件包括：前端操作及 IPC 总耗时、ADB 命令结果、整机报告文件增长、活动后台任务、Renderer 未处理错误和事件循环延迟。网络分阶段、SQLite、哈希、压缩和进程资源采样在确有定位需要时按允许字段继续扩展，不能把任意请求或草稿对象直接写入日志。

日志写入使用有界非阻塞队列和独立写线程。业务线程只尝试投递；队列满时丢弃详细事件并累计计数，不能等待磁盘、持有文件锁或影响 ADB 子进程回收。应用退出时只做有时限的最佳努力刷新。

## 磁盘硬限制

磁盘限制是正确性约束，不是提示：

- 基础日志单文件最多 2 MiB，只保留当前文件和 1 个轮转文件，总计不超过 4 MiB。
- 调试日志单文件最多 4 MiB，只保留当前文件和 4 个轮转文件，总计不超过 20 MiB。
- 启动时清理超过 7 天的诊断日志；固定文件数限制继续生效，即使系统时间异常也不能无限增长。
- 失败 ADB 诊断只保留回执、目录文件元数据以及截断后的 stdout/stderr 尾部。部分 ZIP、截图或其他大型中间文件在写入元数据后删除。
- 失败诊断目录最多保留 3 组、总计最多 12 MiB、最长 72 小时，任一约束超过即从最旧记录开始删除。
- 单份软件证据 ZIP 最大 25 MiB。生成器先按每个文本尾部和 20 MiB 源数据上限计数，超过即停止打包并提示用户；绝不留下超大临时 ZIP。
- 临时软件证据写入根目录下的唯一临时文件，成功检查并复制到最终受管附件后立即删除；失败也必须清理。
- 诊断目录清理失败只记录一次固定错误，不递归写日志，不阻断客户端主要功能。

## ADB 可观测性

ADB 执行器为每次操作记录：命令类别、开始时间、超时上限、是否绑定设备、退出码及 stdout/stderr 字节数。参数值不进入事件，因此设备序列号和包名不会被写入；用户目录在日志层统一替换。

系统报告运行期间每 5 秒记录输出目录已有文件数和总字节数，完成或超时时保存退出码、最终大小和是否生成有效附件。软件证据另附本机 ADB 客户端版本和最近三次报告回执／输出尾部，足以先区分“无法启动、一直无文件、文件持续增长但超时、非零退出和输出无效”；更细的设备生成／主机传输阶段需要真实平台样例后再扩展。

软件证据生成不启动任何设备命令，避免在设备 ADB 卡住时改变现场；只允许执行本机 `adb version` 读取客户端版本，5 秒未返回即记录失败并继续打包。

## 软件证据内容

ZIP 包含：

- `README.txt`：用途、限制和脱敏说明；
- `manifest.json`：格式版本、应用版本、构建平台、架构、生成时间、启动 ID、文件清单、裁剪及丢弃统计；
- `host.json`：应用版本、操作系统、架构、时区、启动 ID、调试状态和本机 ADB 客户端版本；
- `active-operations.json`：生成时仍在执行的任务及最近进度；
- `logs/*`：受大小和时间限制的基础与调试事件；
- `adb-attempts/*`：最近报告尝试的回执和 stdout/stderr 尾部。

软件证据禁止包含 PAT、OAuth Token、请求头、Cookie、云效账号/组织/项目、Bug 标题和描述、Jenkins 地址、`state.sqlite`、用户附件、截图、logcat 正文、完整设备序列号、用户名或未经脱敏的绝对路径。导出前对文本文件再次执行敏感键、URL 凭据、用户目录、序列号和目标包名替换；发现当前凭据字节时拒绝生成附件。

## 附件与生命周期

软件证据沿用 ZIP `report` 附件类型和系统预览能力，来源标记为“Android Bug Desk 软件证据”。归属通过独立 `software-diagnostics` 采集记录保存，不依赖展示文案推断。清理逻辑从只识别 `post-capture` 扩展为读取受信任采集记录中的生成附件 ID，继续执行 UUID、规范路径和父目录检查。

生成顺序为：固定草稿范围 → 刷新日志并创建受限 ZIP → 通过现有附件检查复制到受管目录 → 原子更新草稿和采集记录 → 删除上一份软件证据。账号、组织、项目、草稿状态发生变化时停止写入并删除本次临时文件。

## 实施阶段

1. 建立结构化诊断写入器、动态等级、轮转、时间清理和失败目录限额。
2. 增加本机开发者设置、Bootstrap 字段、设置卡片和自渲染 Switch。
3. 为 ADB 命令、系统报告和前端操作添加允许字段事件；后续按真实证据扩展网络和附件内部阶段。
4. 增加软件证据构建命令、受管附件、重复替换和删除生命周期。
5. 补充三平台路径、文件锁、轮转、磁盘不足、并发采集、敏感信息、模拟超时及 UI 回归测试。

## 验收标准

- 开关默认关闭、即时生效并跨重启保持；退出登录或切换组织不改变它。
- 开关关闭时不显示“软件证据”；开启后显示且无需设备即可生成。
- 调试日志、失败目录和最终 ZIP 在持续高频事件、系统时间异常及清理失败场景下仍不超过各自硬上限。
- 模拟 ADB 无输出、文件持续增长、超时、非零退出和无效 ZIP 时，软件证据记录可核对的进度与结果；设备断开和平台专属阶段分类需要在对应系统验收。
- 软件证据不包含测试注入的 PAT、OAuth Token、用户目录、设备序列号、目标包名、问题正文或 Jenkins URL。
- 重复生成只保留一份草稿附件和一个受管目录；单项移除、移除全部附件及删除草稿均按归属清理生成文件。
- 日志队列拥塞、磁盘写入失败或证据生成失败不阻断设备采集、草稿保存和提交。
- TypeScript、前端测试、生产构建、Rust 测试、fmt、严格 Clippy、实际 React/mock IPC 场景和三平台安装包检查通过。
