# 事后补采证据实施方案

确认日期：2026-10-10。测试人员在 Android Studio 观察日志、复现问题，在本应用补采诊断信息和提交缺陷。用户已确认先落档、再实施。

## 项目包名门禁

设置页的“项目配置”是应用包名的唯一来源。当前项目未填写合法包名时，新建提交主页面只显示阻断提示和“前往设置”入口；表单、设备读取、补采、附件导入、预览和提交均不可用。保存设置后才恢复主页面。

新草稿和旧草稿在读写、采集及提交前都把当前项目配置包名写入 `app.packageName`。“Bug 所在页面”由用户按需填写，设备读取不再读取前台应用或启动持续 Activity 观察。所有需要包名的 ADB 命令、实时会话、事后补采和提交后端再次读取当前账号、组织及项目的已保存映射，不信任渲染层传入的包名。

## 范围与入口

移除“应用与设备”弹窗及其手工输入入口。“证据附件”保留设备连接区，增加两个入口：

- “设备环境快照”直接采集一份可预览的 UTF-8 文本文档并加入附件；
- “补采证据”按问题类型推荐事后诊断项，允许用户增减。

两个入口开始前都重新检查 USB 设备在线且已授权。设备列表曾有该序列号不代表当前可用。导入附件仍不是提交必填项，但只有项目包名配置完成后才可操作主页面。

本轮只采集设备现有信息，不新增实时日志会话、录屏、Perfetto 录制、自动复现、清空日志、重启应用或读取私有数据库。复现视频、现场截图和数据样例由测试人员通过已有附件入口上传。

## 采集项及推荐组合

通用补采默认项为目标应用日志及当前截图。日志按设置页配置包名解析 Android UID，以 UID 同时覆盖主进程、子进程和采集期间的进程重启；UID 无法确定时停止日志采集，不回退整机日志。普通日志只读取 main/system/events，Crash 缓冲区由“崩溃日志”单独负责，避免完全重复。系统报告使用指定设备的整机 `adb bugreport`；ANR 默认选择它以保留线程和系统阻塞上下文，其他问题类型仅作为用户手动勾选的兜底项。环境信息由独立的“设备环境快照”入口获取，不在补采弹窗中重复推荐。

| 问题类型 | 通用项之外默认增加                                                         |
| -------- | -------------------------------------------------------------------------- |
| 功能     | 当前界面层级、应用/进程状态、Activity任务栈                                |
| UI       | 当前界面层级、窗口/显示状态、Activity任务栈                                |
| 多语言   | 当前界面层级、语言/显示配置                                                |
| 动态过程 | 当前界面层级、应用/进程状态、Activity任务栈                                |
| 崩溃     | Crash 缓冲区、可读取的进程退出记录、应用/进程状态、Activity任务栈          |
| ANR      | Crash 缓冲、退出记录、应用/进程、Activity任务栈、窗口/输入、内存、系统报告 |
| 广告     | 应用/进程状态、Activity任务栈                                              |
| 性能     | 内存、现存帧统计、CPU/进程状态                                             |
| 网络     | 当前连接及 DNS/代理/VPN 配置、网络统计                                     |
| 数据     | 存储空间、应用权限及状态                                                   |

“设备环境快照”按固定白名单读取采集时间、厂商/型号/Android 版本/API/构建指纹/ABI、系统语言/时区、屏幕尺寸/密度、内存摘要、磁盘余量、电量、字体缩放、设置中配置的目标包状态及应用语言。它不再读取完整 `getprop`、完整 system/secure/global 设置、connectivity、Wi-Fi 或 `netstats detail`；网络明细由网络专项保留。文档按命令分节，写明目标设备、配置包名、开始/结束时间、逐项成功或失败及原始输出。单项失败仍保留其他结果；文件作为普通文本附件，可通过现有预览入口交给系统文本应用查看。

其他专项使用白名单命令：uiautomator dump、dumpsys activity/package/window/input/meminfo/gfxinfo/cpuinfo/connectivity/netstats、cmd locale、settings 的指定键、`ps -A` 和 df；每项有独立超时和输出限制。Activity任务栈使用目标包过滤后的 `activities` 与 `recents`，只代表系统当前仍保留的任务信息，不是永久操作历史。CPU、窗口和网络专项中的系统上下文对资源竞争、窗口状态、网络路径及流量分析有实质作用，因此继续保留，但只在对应问题类型默认选择。

## 时间与目标语义

- 目标包名取自当前项目已保存映射，不根据草稿旧值或补采时前台页面替换。崩溃后前台为桌面也继续诊断配置应用。未配置包名时任何主页面操作都不能开始。
- 采集起止时间、设备时间和原 Bug 时间分别记录。不得调用旧 mark_problem，修改 event、sessionId、人工输入、问题类型、目标应用或构建身份。
- 当前截图、UI、内存、网络等明确表示补采时状态。历史日志或退出记录只声明实际可见内容，不能承诺覆盖问题时刻、连续窗口或已覆盖的缓冲区。
- 设备/系统不支持、权限不足、无异常记录、空输出、超时和断线分别记录。ADB 不能无条件获取完整 HTTP 业务内容、私有数据或所有 ANR/Native 堆栈。

## 执行、结果及附件

任务固定账号/组织/项目、草稿、设备、包名及问题类型，异步执行。每项独立显示等待、采集中、成功、部分获取、未获取到或失败。慢速 bugreport 放在快捷项之后，统一硬超时为五分钟；界面显示已运行秒数、通常需要 1–3 分钟，以及 Windows 传输可能更久的提示。超时或任务异常退出必须落为失败／中断并回收对应 ADB 子进程，不能永久停在“采集中”。单项失败不停止其他项，也不移除已成功文件。重复点击不能启动同草稿的并行任务，失败项可单独重试。

截图保存 PNG；系统报告保存原 ZIP；文本诊断按采集项保存 ZIP，内含原始文本和机器可读回执，避免将设备快照或未知覆盖的历史日志冒充具备问题窗口覆盖的日志附件。日志回执额外记录目标包名及解析后的 Android UID。回执记录实际命令、起止时间、退出情况、空/失败项及可解析的设备日志时间边界，不把边界当作完整连续覆盖。

同一草稿的结果按采集项合并：弹窗每项只显示最新一次，已成功项再次打开时默认不勾选，用户主动重新勾选后以新附件替换草稿中的该项旧附件，并删除旧生成附件的受管目录。普通补采只保留一份最新整体摘要；独立设备环境快照自身已有完整命令回执，不再额外添加整体摘要。生成 ZIP 和截图时使用根目录短期临时文件，检查并复制到最终附件目录后立即删除；成功的 bugreport 原始输出目录也立即删除，避免与最终附件保存两份。失败或超时的 bugreport 诊断目录继续保留用于排查。历史任务仍保留用于诊断，但不会让弹窗、待上传附件和本地文件随采集次数无限增长。替换不得影响手工导入附件及其他采集项；新采集失败且没有新附件时继续保留旧附件。客户端退出后任务标记中断，已成功附件保留。

macOS 对 ZIP 报告使用系统 Quick Look 预览，避免默认 Archive Utility 在附件目录旁自动解压；图片继续使用系统“预览”，其他平台和格式继续使用系统默认应用。

采集结果继续使用既有附件预览、移除、固定及提交流程。开始/追加时核对草稿仍可编辑和原范围一致；账号或项目切换后停止旧任务的后续采集及写入。未完成任务继续受原有提交前检查保护。

## 实施与验证

新增独立 Rust 补采模块、共享采集项定义、独立 React 补采组件及专项检查；环境快照复用同一持久任务和附件追加边界。移除应用/设备弹窗，不改变既有草稿结构；隐藏字段继续用于云效描述和兼容旧记录，但包名由项目设置强制同步。

本地验证覆盖十类推荐项、设置包名强制来源、无包名主页面门禁、环境快照文本内容、指定设备、断线/未授权、命令失败和空输出、部分成功、重试、任务重复、范围变化、原输入/时间不变、附件完整性和提交冻结。浏览器通过实际 React + 模拟 IPC 验证门禁、进度、错误就近展示、推荐勾选、附件合并及不同窗口布局。运行类型/前端/生产构建/Rust 测试、fmt/Clippy、流程检查及源码指纹保护。

用户随后明确授权直接读取已连接真机。本轮补充真实 USB 设备的采集验证，证据写入独立验证目录，避免混入现有提交草稿；不清空日志、重启应用或修改设备设置。不读取云效凭据、不进行真实云效写入、不打包安装。其他厂商差异和 Windows/Linux 运行验收另行进行。
