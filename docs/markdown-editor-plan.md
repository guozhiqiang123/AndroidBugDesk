# Markdown 图文编辑与云效内嵌图片实施计划

## 1. 目标与范围

以下四个问题字段使用同一套 Markdown 编辑器：

- 问题表现：必填；独占一行。
- 期望表现：选填。
- 复现条件：选填。
- 复现步骤：选填。

编辑器支持正文、标题、粗体、斜体、无序/有序列表、引用、行内代码、代码块、链接和图片。用户可从系统文件管理器复制单张图片，在编辑器聚焦时使用 macOS `Command+V` 或 Windows/Linux `Ctrl+V` 直接插入并预览。首版不支持任意 HTML、表格、文字颜色、字体和远程图片抓取。

现有字符串字段继续保存规范化 Markdown，前端和 Rust 的必填规则保持不变：仅“问题表现”必填，其余三个字段选填。报告、证据清单和历史记录继续从这些字段读取文本，不引入另一份可漂移的描述数据。

## 2. 技术决定

- 编辑器采用 Tiptap/ProseMirror。草稿中的四个字段保存 Markdown 字符串，编辑器内部使用结构化文档。
- 自定义图片节点只保存稳定的本地资源 ID，不保存 `blob:` URL、用户原始文件路径、Base64 或云效临时下载 URL。
- 图片二进制、哈希和远程回执保存在草稿级 `markdownAssets` 资源索引中。
- 图片文件选择、受管目录写入、哈希、MIME 校验和云效上传全部在 Rust 中执行；WebView 只能通过受限命令传入草稿 ID、字段名和剪贴板图片字节。
- 向云效继续提交 `MARKDOWN`。正文图片使用附件接口返回的 `embedMarkdown`，不用临时 `url`，也不切换到未受客户端验证的 RICHTEXT 内容格式。

## 3. 草稿资源模型

草稿新增：

```text
markdownAssets[]
  id                 本地 UUID
  field              actual | expected | preconditions | steps
  name               安全文件名
  path               Rust 管理的绝对路径
  mime               image/png | image/jpeg
  size               字节数
  sha256             内容哈希
  width / height     像素尺寸
  state              staged | unreferenced | local | uploading | uploaded | failed
  remoteId           云效附件或文件 ID，可空
  embedMarkdown      云效返回的永久 Markdown 片段，可空
  embedUrl           云效返回的永久嵌入地址，可空
  error              最近失败，可空
```

Markdown 中使用内部地址：

```markdown
![异常页面](abd-asset://<resource-id>)
```

该地址只在草稿与编辑器中存在。本地证据报告把它替换为证据包内 `markdown-images/` 的相对路径；提交云效前则替换为对应的 `embedMarkdown`。任何缺失、仍在上传或上传失败的被引用资源都阻止提交完成。

资源以草稿为边界，使用 SHA-256 去重。相同内容粘贴多次可共享同一文件，但保留多个文档节点。删除最后一个引用后清理本地受管文件和索引；删除草稿时一并清理。用户通过“导入附件”加入的普通证据不进入此索引。

## 4. 剪贴板图片流程

1. 编辑器捕获浏览器标准 `paste` 事件。
2. 优先读取 `clipboardData.items` 中的图片文件；存在图片时阻止浏览器插入 Base64。
3. 一次粘贴只接受第一张图片；剪贴板同时含图片和文件路径时以真实图片 MIME 为准。
4. 读取字节后调用受限 Tauri 命令，参数仅含草稿 ID、目标字段、MIME、原始名称和字节。
5. Rust 校验草稿归属、实际图片格式、尺寸与容量，复制到草稿受管目录并返回资源记录。
6. 编辑器在当前光标位置插入图片节点，通过受限资源读取命令生成预览。
7. 保存草稿时同时保存 Markdown 与资源索引。

纯文本、Markdown 文本和其他文件维持正常粘贴；不提供通用文件路径 IPC，不读取远程 URL。图片失败显示在对应编辑器下方，不放到整张卡片顶部。

## 5. 云效两阶段提交

云效附件上传要求已有工作项 ID，因此提交采用可恢复的两阶段流程：

1. 冻结草稿并建立不可变证据包。
2. 创建工作项；初始 Markdown 暂时保留不可远程解析的内部资源地址，随后立即进入图片上传阶段。
3. 上传被四个字段实际引用的正文图片，保存返回的 `id`、`embedMarkdown` 和 `embedUrl`。
4. 上传普通证据附件与证据 ZIP；正文图片不重复加入证据上传列表。
5. 根据当前字段 Markdown 生成最终描述，把 `abd-asset://` 引用替换为接口返回的 `embedMarkdown`。
6. 使用 UpdateWorkitem 更新 `description` 和 `formatType: MARKDOWN`。
7. 回读工作项，核对最终描述和全部远程附件后标记提交完成。

每个正文资源的上传状态和远程回执都持久化到提交记录。普通证据附件可按远程 ID、文件名、大小和 SHA-256 回读核对；正文图片若在接收永久嵌入地址前出现不确定结果，则停止自动重传并提示人工核对，避免重复写入。

## 6. 展示和兼容

- 编辑器内图片采用本地预览，离线可见；预览 URL 只存在于当前 WebView 生命周期。
- 编辑状态下每张图片右上角显示关闭按钮，点击只删除当前图片节点；只读提交预览不显示删除入口。保存草稿后继续使用既有的引用扫描和延迟清理，保留撤销删除所需的资源缓冲。
- 工具栏保持单行，只保留撤销、重做、二级标题、粗体、斜体、列表、引用和行内代码入口；移除独占第二行的代码块按钮及能力说明。围栏代码块仍可直接输入 Markdown 语法，图片粘贴能力保持不变，节省出的高度用于扩大正文编辑区。
- 提交预览使用同一 Markdown 渲染规则，并显示未就绪图片状态。
- 旧草稿缺少 `markdownAssets` 时迁移为空数组，原有纯文本按普通 Markdown 打开。
- 云效返回的临时附件 `url` 只用于下载核验，绝不保存为正文图片地址；最终正文只使用 `embedMarkdown` 或 `embedUrl`。
- Markdown 转 HTML 时使用允许列表清洗；链接禁止脚本协议，图片只允许应用本地资源和云效永久 HTTPS 地址。

## 7. 验证与验收

- 四个字段均可输入和保存 Markdown，切换草稿后内容及格式恢复。
- macOS 从 Finder 复制图片后 `Command+V`，Windows/Linux 从文件管理器复制后 `Ctrl+V`，图片出现在当前光标位置并可预览。
- 纯文本粘贴不受影响；非图片文件不会误作为正文资源。
- 问题表现的纯空白 Markdown仍被判定为空；三个选填字段为空时不产生缺失项。
- 图片粘贴、删除、重复粘贴、保存恢复、删除草稿和移除所有附件不会泄漏或误删普通导入附件。
- 图片关闭按钮可正常点击，删除后相邻文字保持不变，当前 Markdown 不再包含该图片引用。
- Mock 云效验证创建、图片上传、`embedMarkdown` 替换、UpdateWorkitem、回读、失败恢复和防重复。
- 运行 TypeScript、前端单元测试、生产构建、Rust 测试、Rust fmt、严格 Clippy和实际 React/mock IPC 场景。
- 真实云效写入和三平台文件管理器粘贴保留为安装包人工验收，不在未授权时执行。

## 8. 实施顺序

1. 引入编辑器依赖并实现通用 Markdown 编辑器。
2. 增加草稿资源结构、迁移、受限图片写入/读取/清理命令。
3. 替换四个输入框并接入粘贴、预览、字段错误和保存恢复。
4. 扩展云效上传响应、提交状态和最终 Markdown 生成。
5. 更新报告、提交预览、测试夹具、Schema 和用户文档。
6. 完成本地与模拟验证；用户授权后再打包安装并进行真实平台验收。
