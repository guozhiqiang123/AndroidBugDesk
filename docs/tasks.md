固定 `bundle:local` 从首次构建即使用 ad hoc 签名，179.2 秒一次生成本机 ARM64 应用和 DMG。签名、架构、DMG、包内应用和安装文件一致性通过后直接覆盖 `/Applications/Android Bug Desk.app`；原生窗口确认前三项显示必填、后三项显示选填，提交前核对只列出前三项缺失。应用持续运行至少 34 秒且没有新增崩溃报告。产物位于 `artifacts/local-required-fields-macos-arm64-20261012/`，DMG SHA-256 为 `ad409782287dff4210f881aeff86b2c0df97f883b721d9c10ca4c810dfd84847`。

## macOS 无响应诊断与轮询收敛（2026-10-13）

安装版无响应时的两次进程采样均显示主线程阻塞在 WebKit/Wry 自定义协议任务的互斥锁等待；现场没有应用所属的 ADB 子进程，ADB 服务也没有持续占用 CPU。设备经历休眠和唤醒后，前端每 1.5 秒允许重叠的完整状态读取会持续经过该协议通道，是当前最可信的触发链，详细证据记录在 `docs/hang-investigation-20261013.md`。

前端状态同步改为单次串行、不可见时暂停、重新聚焦时立即刷新，常规周期调整为 3 秒。主进程新增轮转运行日志和主线程看门狗，并记录设备检查及前台页面观察器生命周期；日志不包含令牌、设备序列号、项目或缺陷内容。版本升级为 `0.2.3`，标签推送后由 GitHub Actions 生成 macOS、Windows 和 Linux 正式安装包。

## Windows 日志采集与自动更新路径兼容（2026-10-13）

部分 Android 设备的旧版 `logcat` 不支持 `--uid`，原实现会直接显示完整帮助文本并将现存日志判定为失败。采集现在优先保留 UID 过滤；不支持时解析目标应用当前 PID，再依次尝试设备端 PID 过滤和本机内存 PID 过滤。最旧设备使用本机过滤时只保存目标进程行及其连续堆栈，其他应用日志立即丢弃；回执明确标记历史覆盖受限，不会把兼容结果描述成完整历史日志。

Windows 自动更新不再假设应用安装在 `%LOCALAPPDATA%\Android Bug Desk`。启动安装器前记录当前进程的真实 EXE 路径，静默安装完成后仅在该文件实际存在时重新启动，避免升级或自定义安装目录下弹出“找不到文件”。

## Windows 整机系统报告超时优化（2026-10-13）

整机 `adb bugreport` 原本统一使用 120 秒硬超时，既有真机成功样例已经需要 99–106 秒，Windows 额外的设备生成和 ZIP 传输开销容易触发误超时。两条系统报告入口现共用 300 秒上限；界面在前三分钟提示常规预计时间，之后明确仍在等待生成和传输，并在约五分钟自动结束。

超时仍只终止并回收本次启动的 ADB 子进程，失败目录和回执继续保留用于诊断，部分文件不会被当作成功附件。超时回执新增实际限制秒数；补采结果对相同的顶层错误和命令错误去重，避免同一超时文案显示两遍。

## 开发者调试与软件证据（2026-10-14）

实施方案已落在 [`software-diagnostics-plan.md`](software-diagnostics-plan.md)。设置页新增独立的“开发者选项”，调试开关按本机持久化且不随云效账号退出而清除。开启后，新建提交页的证据附件区显示“软件证据”按钮；它不依赖 USB 或 ADB 设备连接，可在 ADB 卡住或超时时收集客户端自身诊断。

日志改为后台有界队列和结构化 JSONL。基础日志保留 2 份、每份 2 MiB；详细日志保留当前文件与 4 份轮转、每份 4 MiB，且启动时清理 7 天前文件。ADB 命令记录命令类别、超时、退出状态和输出字节数，不记录参数中的包名或序列号；整机报告每 5 秒记录一次已生成文件数和字节数。失败报告目录最多保留 3 份，每份压缩到 4 MiB 内，成功报告只保留受管附件副本。

软件证据包包含应用／系统版本、ADB 客户端版本、运行日志、活动中的长任务和最近系统报告尝试摘要；打包前再次移除用户目录、凭据、包名、设备序列号与草稿正文。源数据硬上限 20 MiB、最终 ZIP 硬上限 25 MiB。同一草稿再次生成会替换旧软件证据；移除附件或删除草稿会删除对应受管文件，手工导入和本地导出不受影响。

用户已通过本机验收。正式版本统一升级为 `0.3.0`，创建 `v0.3.0` 标签后由 GitHub Actions 构建 macOS、Windows 和 Linux 安装包并发布 Release。

## 自动更新系统代理与下载进度（2026-10-14）

Windows 安装版此前无法读取常见的当前用户系统代理，且下载安装包时会整包驻留内存、最长 15 分钟只显示固定文案。实施前先将根因、代理边界、下载状态、隐私规则和验收标准落在 [`update-network-plan.md`](update-network-plan.md)。

更新请求现启用系统代理与系统证书根；环境变量代理仍优先。安装包改为分块写入 `.download` 文件并同步计算 SHA-256，连续 45 秒无数据即失败并清理临时文件，下载总量继续受 GitHub 声明大小和 512 MiB 双重限制。更新弹窗通过 Tauri Channel 显示连接、下载百分比、大小、速度、校验和准备安装阶段。运行日志只记录代理来源类别和错误类别，不保存代理地址、凭据或下载 URL。

专项 Rust 测试覆盖流式写入、哈希校验、进度单调递增和停滞超时清理；实际 React/mock IPC 覆盖启动更新提示、取消、下载进度及失败恢复。完整验证通过 188 项前端测试、183 项 Rust 测试（3 项外部环境测试按设计忽略）、类型检查、生产构建、Rust 格式、严格 Clippy、20 项发布包测试、10 项流程测试、53 个完整浏览器场景和 2 个启动更新专项场景。本轮不打包、不安装，也未执行真实版本升级。
