# Bug 所在页面采集修正计划

日期：2026-10-12
状态：已完成

## 背景与问题

当前客户端在进入“新建提交”、刷新设备或切换设备时读取一次系统前台 Activity，并把任何非系统浮层应用都写入 `bugPage`。真实提测中，问题发生后应用已经崩溃并返回桌面，因此报告记录成了 `com.google.android.apps.nexuslauncher.NexusLauncherActivity`。这个值描述的是设备读取时的桌面，不是问题发生前的目标应用页面。

现有实现还存在三项关联问题：

1. 前台包名没有与设置页中当前项目的 Android 包名比对。
2. 后续自动读取到非空值时可能覆盖用户人工修正的页面。
3. 主页面和提交预览没有展示 `Bug所在页面`、采集时间和来源，用户提交前无法核对。

## 目标行为

1. 只有前台组件的包名与当前项目包名完全一致时，才把 Activity 记为 `Bug所在页面`。
2. 设备选定且草稿可编辑期间，由 Rust 主进程持续观察前台 Activity，保存最近一次目标应用页面。应用崩溃、退到桌面或切到其他应用后保留最近一次有效值。
3. 没有观察到目标应用时保持为空；读取到桌面、系统界面或其他应用只记录为未采用的观察结果，不写入报告页面字段。
4. 用户人工修改后，自动采集不得再覆盖该值。清空也视为人工决定。
5. 主页面增加 `Bug所在页面（选填）`，显示当前值、来源和采集时间；提交预览和最终报告同步展示可核对的来源信息。
6. 自动采集时间使用成功读取前台组件时的时间，不复用设备快照开始时间。

## 实施方案

### 1. 目标包过滤

- 提取“前台组件转目标页面”的纯逻辑，只接受 `foreground.package == configuredPackage`。
- 保留 activity/window 一致性校验；相对 Activity 名补全为完整组件名。
- 初次设备快照遇到其他包时返回空页面及非阻断来源说明，不把 Launcher 写入草稿或报告。

### 2. 主进程持续观察

- 在 `AppState` 中维护单个页面观察任务。成功读取设备后启动；重新选设备时替换旧任务。
- 每秒读取一次经过现有安全解析的前台组件；只有命中目标包且页面发生变化时才写草稿，避免无意义磁盘写入。
- 切换账号／项目、修改项目配置、新建或删除草稿、退出应用时停止旧任务；草稿被冻结、删除、范围变化或包名变化时任务自行结束。
- 观察任务只更新 `bugPage`、对应来源、预览确认状态和更新时间，不修改设备、附件或其他人工字段。

### 3. 并发与人工值保护

- 人工编辑 `bugPage` 时，renderer 立即把来源标记为 `manual`。
- 保存草稿时区分“人工编辑”和“后台观察后 renderer 尚未刷新的旧值”：人工值可以写入，旧自动值不能反向覆盖主进程刚采集的页面。
- 自动快照和持续观察均尊重 `manual` 来源；只有用户再次编辑才能改变人工值。
- 页面自动变化后，renderer 从本地草稿同步页面和来源，同时保留其他尚未保存的表单输入。

### 4. 展示与报告

- 在问题信息区将 `Bug所在页面（选填）` 放在问题表现之后并独占一行。
- 来源显示区分自动采集、人工补充和未采纳观察，并显示具体时间和说明。
- 提交预览展示页面、来源和采集时间；页面为空时明确显示“未采集”。
- 云效描述和本地 `report.md` 只在页面非空时输出页面；有值时追加对应来源和采集时间。清单继续保留结构化 `sources.bugPage`。

## 验收条件

1. 目标包为 `com.photo.recovery.global.tt`，前台为 Nexus Launcher 时，`bugPage` 为空或保留此前目标应用页面，报告中不得出现 Launcher Activity。
2. 前台依次为目标应用 A 页面、目标应用 B 页面、Launcher 时，最终保留 B 页面及其实际采集时间。
3. 前台包名相同且 Activity 使用相对名称时，保存为完整组件名。
4. 用户人工填写或清空页面后，刷新设备及后台观察都不覆盖人工值。
5. 后台观察写入后，用户保存其他表单字段不会把页面回滚成 renderer 的旧值。
6. 切换设备、项目、账号或删除草稿后，旧观察任务不再写入。
7. 主页面、提交预览、云效描述和本地报告对页面值、来源和时间的展示一致。
8. 前端测试、Rust 测试、类型检查、生产构建、Rust 格式和严格 Clippy 全部通过。

## 实施结果

已按上述顺序完成。主进程每秒观察一次安全解析后的前台组件，只在包名与项目映射完全一致时保存页面；目标应用退出或崩溃后保留最后一次有效页面。观察任务具有代际保护，切换范围或停止任务后旧任务不能继续写入。旧草稿中由旧版自动采集的非目标页面会在启动时清理，报告和清单生成时另有目标包防线。

人工填写及人工清空均优先于自动值；后台观察与表单保存并发时不会用 renderer 的旧值回滚页面。主页面和提交预览显示页面、来源及采集时间，云效描述和本地报告在页面有效时输出相同信息。

验证通过：187 项前端测试；167 项 Rust 测试，3 项需要外部设备或真实账号的测试按设计忽略；TypeScript、生产构建、Rust 格式、严格 Clippy、Prettier 和差异检查；52 个实际 React/mock IPC 场景。浏览器证据位于 `artifacts/ui-bug-page-capture-20261012/browser-final/`。本轮没有打包安装、主动读取真实 USB 设备或写入真实云效。
