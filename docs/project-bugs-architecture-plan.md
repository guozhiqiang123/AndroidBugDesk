# 项目 Bug 工作台与数据架构收敛计划

## 1. 背景与目标

Android Bug Desk 已同时承担草稿编写、设备取证、云效提交、历史查询、软件诊断和更新等职责。继续把新状态、接口调用和业务判断直接加入 `main.tsx`、`commands.rs` 或现有“历史提交”模块，会让账号、项目、草稿和远端请求的生命周期互相影响，增加串数据、过期响应覆盖新状态和登录失效后页面不一致的风险。

本次先建立统一边界，再新增顶层“项目 Bug”页：

- 展示当前主页面所选项目下、当前账号有权限读取的全部 Bug，不限制为本人创建。
- 支持服务端分页、筛选和排序，避免把几十个项目或整个项目的数据一次性拉到本机。
- 保留“历史提交”的原有含义：本机提交记录和本人云效历史，用于回溯本客户端产生的提交。
- 新功能只消费当前工作区的账号、组织和项目，不另建项目选择器，不改变主页面项目绑定。

## 2. 架构决定

### 2.1 按数据所有权管理状态

| 数据                     | 所有者           | 保存位置                      | 生命周期                           |
| ------------------------ | ---------------- | ----------------------------- | ---------------------------------- |
| 草稿、证据、提交回执     | Android Bug Desk | SQLite 与受管文件目录         | 跨启动持久化                       |
| 当前账号、组织、项目     | 工作区会话       | `AppState` 与前端会话         | 登录或项目切换时更新               |
| 云效 Bug 列表            | 云效             | 不落 SQLite，前端只保留当前页 | 打开页面、筛选、翻页或刷新时重取   |
| Bug 查询条件             | “项目 Bug”功能   | 对应页面组件                  | 页面打开期间；离开或项目切换时清空 |
| 成员、标签、状态等筛选项 | 云效项目元数据   | 当前页面内存                  | 按账号、组织、项目作用域失效       |

远端列表不复制成本地事实来源。这样不会出现云效已修改而本地缓存仍显示旧状态，也不会让草稿数据库承担通用远端数据仓库职责。

### 2.2 统一远端工作项查询层

后端分为四层：

1. **Tauri 命令边界**：反序列化和校验参数，只返回稳定 DTO。
2. **工作区查询服务**：读取账号、组织、项目和认证纪元快照，执行完成后再次核对作用域，拒绝登录或项目切换前发起的过期结果。
3. **云效工作项适配器**：统一实现 `SearchWorkitems` 的请求、响应头分页、错误映射和登录失效识别。
4. **功能查询模块**：分别组装“本人历史”和“项目 Bug”的筛选规则；两者复用适配器，但不复用业务约束。

现有历史查询会迁移到统一适配器，继续强制 `creator = 当前用户`。项目 Bug 查询不加入该条件。以后需要看板、统计或其他工作项列表时，应增加新的功能查询模块，禁止复制 HTTP 请求代码。

### 2.3 前端按功能隔离

新增独立模块：

- `src/shared/project-bugs.ts`：查询、筛选、排序、分页和列表 DTO。
- `src/renderer/project-bugs-view.tsx`：页面、请求竞态控制和交互状态。
- `src-tauri/src/project_bugs.rs`：工作区作用域校验和云效查询编排。

`main.tsx` 只负责顶层 Tab 路由并传入当前工作区资料。新页面不读取或修改草稿，不把查询状态加入全局 Bootstrap，也不继续扩大历史模块。

### 2.4 并发、认证与错误边界

- 每次查询绑定 `{userId, organizationId, projectId, authEpoch, workspaceEpoch}`。
- 项目切换、退出登录或登录过期后，旧请求即使稍后返回也不能更新页面。
- 前端为列表和筛选项分别维护递增请求序号；只接收最新请求结果。
- 认证失败继续走全局登录失效流程，清理会话并回到登录页。
- 筛选变化回到第一页；分页每页最多 50 条；不在客户端循环抓取整个项目再筛选。
- 页面只在首次打开、用户刷新、提交筛选或翻页时请求，不做后台轮询。

## 3. 云效能力与首版范围

首版使用官方 `SearchWorkitems`：`category=Bug`、`spaceType=Project`、`spaceId=当前项目`。筛选条件使用一个 AND 组，多选值在字段内部使用 OR 语义。

首版提供：

- 标题关键词。
- 状态（多选）。
- 负责人（多选）。
- 创建者（多选）。
- 标签（多选）。
- 创建时间范围。
- 创建时间升序/降序。
- 服务端分页和总数展示。

列表展示标题、编号、状态、负责人、创建者、创建时间和更新时间，并可在系统浏览器打开云效详情。排序首版只开放官方文档明确支持且能稳定映射的创建时间排序；其他列不做伪排序，也不对单页数据排序后冒充全量排序。

状态选项通过工作项类型的工作流接口读取；成员、标签和 Bug 类型复用项目元数据读取能力。若项目存在多个 Bug 类型，状态集合按 ID 去重。接口没有返回的筛选项显示为不可用，不退化为拉取全量 Bug 后本地推断。

接口依据：

- [SearchWorkitems：搜索工作项](https://help.aliyun.com/zh/yunxiao/developer-reference/searchworkitems)
- [GetWorkitemWorkflow：获取工作项工作流状态](https://help.aliyun.com/zh/yunxiao/developer-reference/getworkitemworkflow-get-a-list-of-the-status-of-the-work-item)

## 4. 数据契约

前端传入严格查询对象：

```text
ProjectBugQuery
  page                 从 1 开始
  perPage              1..50
  keyword              可空
  statusIds[]
  assignedToIds[]
  creatorIds[]
  tagIds[]
  createdFrom          YYYY-MM-DD，可空
  createdTo            YYYY-MM-DD，可空
  sort                  created_desc | created_asc
```

后端返回：

```text
ProjectBugPage
  items[]
  page / perPage
  total / totalPages       云效响应头缺失时可空，页面退化为本页数量和是否有下一页

ProjectBugFacets
  statuses[]
  members[]
  tags[]
```

后端拒绝未知排序值、非法日期、越界页大小和非法 ID 形态。云效返回值经过 DTO 映射，React 页面不直接依赖供应商响应结构；已删除但格式仍合法的筛选 ID 交给云效按空结果处理，避免每次翻页额外读取一遍元数据。

## 5. 实施步骤

1. 提取通用 `SearchWorkitems` 请求与分页解析，先用现有历史测试锁定兼容行为。
2. 建立“项目 Bug”共享契约和 Rust 查询模块，接入作用域快照与认证失效处理。
3. 实现筛选项读取，覆盖多 Bug 类型状态合并、成员与标签去重。
4. 新增顶层 Tab 和独立页面，完成筛选、排序、分页、刷新和打开详情。
5. 增加 Rust Mock API 测试、TypeScript 查询状态测试和浏览器模拟；执行完整检查。
6. 在实现完成后回写本文档的实施结果及尚需真实账号验证的边界。

## 6. 验收标准

- “项目 Bug”只展示当前主页面所选项目的数据，且不限制创建人。
- 切换项目后旧项目结果立即失效，新查询不会混入旧数据。
- 筛选和创建时间排序作用于服务端全量结果；翻页不会丢失筛选条件。
- 登录过期时回到登录页，不把认证错误渲染成空列表。
- “历史提交”仍只展示本机记录和本人云效历史，筛选、分页及恢复操作不变。
- `main.tsx` 不承载项目 Bug 的业务查询；HTTP 搜索请求只有一个适配器实现。
- TypeScript 检查、前端测试与生产构建通过；Rust 格式、测试和严格 Clippy 通过。

## 7. 后续演进规则

- 新的远端列表功能必须声明数据所有者、缓存周期、作用域键和过期响应处理方式。
- 草稿数据库只保存本应用产生且需要恢复的数据；云效可随时重新读取的列表不持久化。
- 供应商字段、筛选条件和响应结构只能出现在后端适配器及映射测试中。
- 超过一个页面复用的项目元数据再提升为带作用域键的内存仓库；在复用发生前不引入长期缓存和手工失效复杂度。
- `main.tsx` 只做应用外壳、导航和跨功能协调；新增业务状态必须进入独立功能模块。

## 8. 实施结果（2026-10-16）

- 新增顶层“项目 Bug”页，绑定主页面当前项目，首次打开时读取当前项目全部 Bug；页面提供标题、状态、负责人、创建者、标签和创建日期范围筛选，以及创建时间正序/倒序和服务端分页。
- 提取统一 `SearchWorkitems` 适配器，集中处理单项目 Bug 范围、请求体、分页响应头、只读重试和页大小限制；个人云效历史和未知创建结果核对已迁移到该入口。
- 提取只读工作区快照，统一绑定用户、凭据、组织、项目及认证/工作区纪元；个人历史和项目 Bug 都在网络返回后检查快照，避免账号或项目切换后的旧响应落入新页面。
- 项目目录和表单元数据已经成为项目切换、新草稿和筛选项共同依赖的数据，因此提升为按用户、组织、项目和 Bug 类型隔离的五分钟内存缓存；退出登录会清空缓存，“刷新云效配置”始终绕过字段缓存。云效字段、成员、版本和迭代读取改为并行请求，使用刚刚由后端验证过的项目目录切换时不再重复访问组织和项目列表。
- 项目 Bug 使用独立 Rust、TypeScript 和 React 功能模块；远端列表不写 SQLite，筛选项只在页面内存中保存，账号或项目变化通过组件作用域键整体重建。
- 状态从每种 Bug 类型的工作流读取并按 ID 去重；成员和标签优先复用当前项目元数据，缺失时通过项目只读接口补齐。非认证类的标签或单类型状态读取失败会显示局部提示，不把可用列表整体清空。
- 已增加官方筛选结构、跨创建人结果、分页总数、工作流状态合并、日期校验和查询状态隔离测试。真实云效账号下的项目规模、权限组合和字段差异仍需在安装包中人工验收。
