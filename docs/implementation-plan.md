# Android Bug 提交桌面客户端实施计划

日期：2026年10月9日。面向后续实施会话与测试团队。

开发一个供测试人员使用的桌面辅助客户端：通过 USB 连接 Android 真机，自动收集设备、应用和问题日志，补齐人工信息，上传截图、视频及证据包，并通过测试人员自己的个人访问令牌向阿里云效创建缺陷。必填信息未齐时不能提交；提交成功后，开发人员和 Multica 可以从同一条缺陷获得可定位、可追溯的证据。

本计划采用 macOS 与 Windows 双平台方案，具体发布平台在实施开始时确认。当前交付物是实施计划，客户端、云效附件上传、Jenkins 归档改造及应用诊断导出尚待实施。

## 1 首版范围和完成标准

### 1.1 用户要求对应的功能

| 用户要求                                 | 首版实现                                                                     | 完成标准                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| ADB 能采集的关键信息直接采集             | USB 设备识别、设备与应用快照、持续日志、问题时间标记、一键截图、按需系统报告 | 选定设备后自动采集，显示成功项和失败项，不让用户重复抄录               |
| 内部集成云效 API，进入应用填写个人 Token | 首次进入授权向导；填写个人 PAT，校验项目访问；可选择在本机加密保存           | 使用该用户权限创建 Bug，Token 不进入日志、证据包或云效描述             |
| 采集不到的信息人工填写                   | 复现步骤、预期与实际结果、渠道、固定 Jenkins 构建链接、云控状态等            | 自动值与人工值均有来源；缺项有明确输入控件                             |
| 必填项未填不能提交                       | 页面校验和桌面主进程校验使用同一规则；合并云效项目实际必填配置               | 任一必填缺失、类型错误或构建身份冲突时，创建 API 调用次数为零          |
| 支持截图和视频上传                       | 选择文件、拖入文件、截图粘贴、一键设备截图；视频文件附件上传                 | PNG/JPEG、MP4 在指定验收项目真实上传、读取、下载通过；预览能力单独验证 |

### 1.2 工作流边界

- 本客户端负责“测试发现问题 → 收集证据 → 人工确认 → 创建云效缺陷”。这里使用的是云效 Projex 的工作项创建和附件 API。
- 现有内网版本提测平台仍是 `http://qa.ludashi.com/index.php`，其最终提交继续由人工完成。客户端中的“提交 Bug”按钮由测试人员点击，直接调用云效 API。
- 不要求测试人员安装 Multica、配置 AI 模型密钥或提供 Git 仓库；首版提交能力独立可用。
- 不自动将新缺陷标记为“处理中”“已解决”，不修改已有开发修复流程，不自动触发 Jenkins 打包或生产构建。
- 暂不实现无线调试、iOS、自动操作手机复现、性能录制全家桶或云控后台管理。真机录屏的一键控制可在基础上传闭环之后增加；首版必须支持导入现成视频。

### 1.3 首版整体完成标准

测试人员在安装后的桌面应用中完成一次真实演练：个人 Token 授权，连接真机，选择目标包和 Jenkins 固定构建，启动日志，复现并标记问题，补齐描述和云控信息，添加截图与 MP4，预览后提交。云效中能看到正确项目、负责人、版本范围和全部证据，客户端返回真实缺陷链接，失败重试不重复创建缺陷。

## 2 推荐技术方案

采用 Electron、TypeScript 和 React。该方案便于统一桌面界面、调用 ADB 子进程、执行文件上传，并在两个平台共享主要业务代码。实施时选择当时受支持的稳定版本并锁定依赖，不在计划中固定易过期的版本号。

建议结构：

```text
桌面界面
  授权向导 / 测试会话 / Bug 表单 / 附件预览 / 提交记录
       ↓ 受限的本地通信接口
桌面主进程
  CredentialStore    个人令牌保存和读取
  ProjectProfile     项目配置和字段映射
  AdbService         设备识别、快照、日志和截图
  SessionStore       会话、草稿和提交状态
  EvidenceBuilder    报告、清单和证据包
  ValidationService  必填项与构建冲突校验
  YunxiaoClient      字段查询、创建缺陷、附件上传与回读
  JenkinsResolver    构建链接与清单解析，后续增强
```

主进程负责凭据、ADB、文件和网络；界面不能任意执行命令或读取文件。开启上下文隔离、关闭界面 Node 集成，通信接口校验参数；渲染云效或用户输入的 Markdown 时过滤 HTML。具体实现参考 [Electron 安全文档](https://www.electronjs.org/docs/latest/tutorial/security)。

本地草稿、提交状态建议使用 SQLite 事务保存，附件使用应用数据目录下的独立文件夹。所有 ADB 调用使用固定参数数组，校验设备序列号和包名，避免拼接用户输入为 shell 命令。网络请求使用标准 HTTP 客户端直接访问官方 REST API，不经由 AI 或 MCP 代执行。

## 3 测试人员的操作流程

### 3.1 首次进入

1. 填写个人云效 PAT，选择“仅本次使用”或“在本机保存”。密码式输入框默认隐藏内容。
2. 导入或选择项目配置，展示组织、云效项目和业务方向。
3. 使用只读请求校验项目访问，加载 Bug 类型、字段配置、成员、迭代和版本。显示“项目读取已验证”；没有实际写入验证时，不宣称创建和附件权限均已验证。
4. 检测 ADB 位置。优先使用已安装 Android SDK Platform Tools，缺失时提供官方安装入口和选择路径功能。
5. 连接真机并开启 USB 调试。未授权、离线、多设备等情况分别给出中文处理说明。所有采集绑定用户明确选中的设备。

以后进入应用：已选择保存且凭据可用时恢复授权；未保存、已过期或被撤销时重新填写。Token 无效不删除已有草稿，仍能本地采集和导出，禁止网络提交。

### 3.2 开始测试

用户选择业务方向、安装包、固定 Jenkins 构建号链接、版本或迭代范围，然后点击“开始采集”。客户端生成会话 ID，采集初始快照并持续保存日志；页面显示正在记录的设备、包名、版本和构建。

同一会话中可以记录多个 Bug。每个 Bug 有独立问题 ID、时间标记和附件；共用会话背景信息，但保存问题发生时的快照。切换设备、安装新包或变更构建时，结束原会话并建立新会话，避免证据串包。

### 3.3 记录问题

点击“记录问题”立即保存电脑时间、设备时间和当前快照，并尝试截取设备屏幕。之后填写现象和复现步骤，添加截图或视频。日志继续记录一段问题发生后的内容。

如果问题发生后才开始采集，必须填写真实发生时间、注明“事后补采”，并导入已有证据或重新复现；采集开始时间不能冒充问题发生时间。用户可以修改自动时间，但必须保留原始值和修改来源。

### 3.4 补齐和提交

表单展示“待补充”列表，点击可跳到对应字段。必填缺失时按钮显示“还有 N 项待补充”，同时允许保存草稿；信息齐全后才能进入提交预览。

预览包含云效项目、方向、负责人、版本范围、构建身份、描述、采集失败项和附件。测试人员点击“提交 Bug”后才执行写入，上传期间展示各阶段进度。成功后提供缺陷编号、真实链接、复制链接和打开云效按钮。

## 4 采集清单与人工补充

ADB 来自 Android SDK Platform Tools，USB 调试需要手机授权；多设备使用明确的目标设备参数。见 [ADB 官方文档](https://developer.android.com/tools/adb)。下表是采集器设计，应通过支持的 Android 版本和厂商设备实测输出格式；不假设每项命令在所有设备均可用。

| 信息                               | 自动采集方法或来源                                                                      | 失败或不可确定时                                                         |
| ---------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 设备识别                           | `adb devices -l`，显式绑定序列号；查询当前 Android 用户                                 | 处理连接与授权问题；不能用另一台设备的快照替代                           |
| 厂商、型号、Android、API、ROM、ABI | 逐项 `getprop` 查询指定属性，保留系统构建指纹                                           | 对关键缺失字段提供人工输入，保留采集错误                                 |
| 总内存与当前可用内存               | `/proc/meminfo` 中的实际字段，优先使用 MemAvailable；必要时记录 MemFree                 | 不把 MemFree 当成 MemAvailable；人工输入必须注明来源和单位               |
| 存储剩余空间                       | 读取 `/data` 文件系统容量；保留统计时间                                                 | 展示无法读取并要求相关问题补充设备设置截图或数值                         |
| 屏幕                               | `wm size`、`wm density`，记录物理值和覆盖值；读取字体缩放、方向                         | 明确像素分辨率与密度；不根据型号臆测物理英寸                             |
| 应用身份                           | 目标用户的包列表、`dumpsys package`，解析包名、versionName、versionCode、安装和更新时间 | 允许从系统应用详情或包信息手动填写，记录证据来源；已有值冲突不能静默覆盖 |
| 应用内存                           | `dumpsys meminfo <package>` 的问题前后快照                                              | 按需采集，失败不伪造为零                                                 |
| 网络与权限                         | 可读取的连接状态、目标包权限和 appops 摘要                                              | VPN、代理、弱网操作、权限设置是否刚变更等由用户确认                      |
| 电量与后台条件                     | 可读取的电池与电源状态；按需读取后台限制                                                | 人工确认省电模式、厂商后台设置；不自动改变系统设置                       |
| 日志                               | 开始复现前记录 main、system、crash 等所需缓冲区；派生应用相关摘要                       | 导入人工取得的日志；没有非空日志证据时不能完成必填日志项                 |
| 问题时间                           | 电脑和设备时间、时区、问题标记、会话单调计时                                            | 时钟差保存为估计值及精度，断线和跳时需标记；人工补报必须标出来源         |
| 截图                               | `exec-out screencap -p` 二进制保存；另支持文件导入及剪贴板图片                          | 受安全窗口限制等原因失败时提示导入外部拍摄或录屏，不绕过设备限制         |
| 系统报告                           | 崩溃、ANR 等问题按需 `adb bugreport`                                                    | 设备不支持时保留失败记录；不以不存在的报告或空文件完成证据项             |
| 视频                               | 首版导入 MP4；增强阶段支持设备 `screenrecord`、停止和拉取                               | 使用者导入真机录屏或外部拍摄视频；一键录屏能力按设备协商                 |
| 渠道、混淆和加固                   | 优先从可信构建清单或应用诊断导出读取                                                    | 用户明确选择和确认，不能根据 versionCode 推断                            |
| 有效云控与实验                     | 应用诊断导出接口接入后采集                                                              | 首版由用户填写实际观察到的生效值、来源、时间并附证明材料                 |
| 现象与复现                         | 人工输入                                                                                | 必须包括前置条件、顺序步骤、预期和实际结果                               |

### 4.1 日志规则

- 不在采集前自动清空手机日志；先保存已有缓冲区，再启动持续记录，并处理重复记录。
- 不仅按某一个固定 PID 过滤原始采集，避免应用重启、多进程及系统崩溃信息丢失。应用相关摘要可另行生成。
- 原始记录保留时间、PID/TID、日志等级等信息，保存实际起止时间、断线间隔和采集错误。容量采用本地轮转；问题附近的文件片段先固定，不能因继续测试被淘汰。
- 首版建议问题摘要覆盖标记前约 2 分钟和标记后约 30 秒，均作为可调整产品参数；没有覆盖到完整窗口时如实记录。
- Android 日志是循环缓冲区，部分日志可能被编译移除；没有日志不能证明没有发生问题。见 [Logcat 官方文档](https://developer.android.com/tools/logcat)。
- 常规 Bug 不强制完整系统报告；崩溃和 ANR 可增加专项报告。普通真机不能假定有 root 或能读取 `/data/anr`、应用私有目录和 native tombstone。系统报告方案参考 [Android Bugreport 文档](https://developer.android.com/studio/debug/bug-report)。

### 4.2 云控信息

首版必须提供结构化人工输入：配置或实验名称、设备实际生效值、判断来源、观察时间，以及是否存在测试覆盖值。来源可选“应用调试面板”“应用导出”“相关运行日志”“用户可观察行为”；后台配置截图可以补充，但不能代替设备生效证据。

与云控相关的问题，实际生效值与来源必须填齐。确认该功能无云控时，选择“不适用”并填写功能依据；没有拿到生效值时保持草稿并提示如何补齐，不用“未知”“稍后补”等文本冒充必填信息。

后续应用诊断导出建议包含：默认值、缓存或远端来源、最后拉取和激活时间、实验分组、调试覆盖项、与故障相关的订阅及广告等业务状态。导出必须是测试包可控能力，不向生产包开放无保护的诊断端口。

## 5 必填项和提交门槛

实际必填规则取三者并集：客户端基础规则、所选项目规则、云效 Bug 类型字段配置中的 required 字段。字段展示与值转换根据配置进行，不能只做一份固定表单。云效接口会返回字段格式、选项及 required 等信息，见 [GetWorkitemTypeFieldConfig](https://help.aliyun.com/zh/yunxiao/developer-reference/getworkitemtypefieldconfig)。

### 5.1 基础必填

| 字段                 | 校验规则                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| 授权与项目           | 提交时存在有效 Token；组织、项目与 Bug 类型已匹配并有可访问元数据                                  |
| 业务方向             | 新马甲包、Launcher 或其他已配置方向，不能从共享仓库目录猜测                                        |
| 标题与类型           | 非空且有具体行为；类型选择功能、UI、崩溃、ANR、性能、网络等                                        |
| 负责人及项目必填字段 | 从该项目真实成员和枚举选项选择 ID；不硬编码姓名或优先级 ID                                         |
| 版本范围             | 至少选择真实云效版本或迭代之一；若团队用渠道或自定义版本字段，须配置等效范围规则并填写准确值       |
| 应用身份             | 包名、versionName、versionCode、渠道，以及测试环境和混淆/加固状态；versionCode 接受 0 等有效整数   |
| 构建来源             | 固定 Jenkins 构建号 URL；拒绝 job 首页、lastBuild、lastSuccessfulBuild 等会变化的链接              |
| 设备背景             | 型号、Android 版本、总内存、当前可用内存、像素分辨率、屏幕密度；自动失败后显示对应人工补充项与来源 |
| 问题时间             | 有时区的事件时间；自动标记或明确人工补报，区分采集时间                                             |
| 前置条件             | 新装/升级、是否清数据、账号或订阅状态、相关权限、网络状态等与本次操作有关的事实                    |
| 复现步骤             | 至少一条可执行的有序步骤，不能只有“打开看一下”一类无定位内容                                       |
| 结果                 | 预期结果与实际结果分别填写，不合并为一个模糊描述                                                   |
| 复现频率             | 已尝试次数和出现次数，或明确“首次发现、尚未重复”；不填虚构概率                                     |
| 日志证据             | 至少一份非空的自动日志或导入日志，记录来源及覆盖时间；不能用截图代替日志文件                       |
| 云控声明             | 填齐适用的设备生效信息；不适用必须有原因                                                           |
| 预览确认             | 用户确认项目、构建、描述和将上传的附件内容                                                         |

### 5.2 条件必填

- UI、布局、多语言和显示问题：至少一份截图或视频；动态过程问题要求视频或能够表达顺序的多张截图。
- 崩溃、ANR：必须有相关日志或系统报告附件；是否包含完整异常栈、ANR 线索等另做证据质量提示，缺少线索不能标记为“已具备精确定位证据”。
- 网络问题：填写操作、网络类型、发生时间、可观察错误；已有错误码、请求 ID 则补充，无法取得时注明采集状态。TLS 解密或全量抓包不作为首版能力。
- 扫描、恢复、导入等数据相关问题：填写数据类型、数量、来源及必要的样例。样例文件仅在定位确有需要且测试人员确认时上传。
- Jenkins 清单与设备包名、版本或已验证的安装产物身份冲突：阻止提交，重新选择实际构建。映射文件暂未归档可以标记为开发侧待补，不能伪造其已匹配。

### 5.3 规则实现

字段缺失时既在控件旁提示，也给出待补清单。自动采集失败不等于该必填项通过，人工补充后保留 auto_failed 和 manual 来源。空白、只有占位文本、零字节文件、过期选项 ID 均不能通过。

主进程重新验证整个草稿和附件，即便界面按钮被绕过也不能提交。提交前刷新或核对字段配置；遇到项目新必填项、无法支持的必填字段格式或权限失效，保留草稿并停止写入。禁止为让请求成功而静默删掉无法映射的字段。

## 6 阿里云效 API 接入

### 6.1 接入和个人授权

使用官方 PAT REST API：请求头 `x-yunxiao-token`。中心版接入点为 `https://openapi-rdc.aliyuncs.com`，路径包含 organizationId；Region 版使用实例接入点且路径不同。首版实现当前中心版，在配置层区分环境，避免替换域名后仍沿用错误路径。参考 [服务接入点](https://help.aliyun.com/zh/yunxiao/developer-reference/service-access-point-domain) 和 [个人访问令牌](https://help.aliyun.com/zh/yunxiao/developer-reference/obtain-personal-access-token)。

每位测试人员填写自己的 Token，不共享当前协调员 Token，不收集云效登录密码。用户可修改或清除保存的授权；更换用户后重新加载有权限的项目与成员，不沿用其他用户的授权结果。

保存方式采用 Electron safeStorage 的系统保护能力，加密后保存本地密文；macOS 使用钥匙串保护密钥，Windows 使用 DPAPI。加密能力不可用时，只能本次内存使用，不能回退到明文文件。Windows 的保护不隔离同一用户下的其他程序，不能声称防御本机被攻陷。参考 [safeStorage 官方文档](https://www.electronjs.org/docs/latest/api/safe-storage)。

### 6.2 权限清单

| 云效项目协作资源   | 权限 | 用途                                       |
| ------------------ | ---- | ------------------------------------------ |
| 工作项             | 读写 | 创建缺陷、回读和在上传后补全受管理描述段落 |
| 工作项附件         | 读写 | 上传截图、视频、日志和证据包，读取附件列表 |
| 工作项类型         | 只读 | 查询该项目 Bug 类型                        |
| 工作项类型字段配置 | 只读 | 动态必填校验及枚举选项                     |
| 项目成员           | 只读 | 负责人、验证人等选择                       |
| 版本、迭代         | 只读 | 范围绑定，按启用功能申请                   |
| 项目               | 只读 | 读取项目、名称及项目选择，按配置方式申请   |

不因客户端接入而要求代码库、流水线等其他产品的全量权限；首版不依赖评论写入和项目字段管理。项目成员自身的资源访问权限也需满足，PAT 勾选权限不代表自动取得项目权限。

现有 Mac 工作流令牌曾验证工作项读取，工作项权限已改为读写；其工作项附件权限仍为只读，不能直接作为客户端附件上传已可用的证明。此次计划不读取该令牌、不修改其权限，实施时使用测试人员新填写的个人 PAT。

以下相对路径均以中心版前缀 `/oapi/v1/projex/organizations/{organizationId}` 为基准。详细字段以对应官方文档和实施时验证为准。

新缺陷初始状态遵循项目实际工作流；接口契约阶段确认真实默认状态，不在客户端直接套用此前修复流程的状态 ID。

### 6.4 截图和视频支持结论

官方接口支持 multipart 文件上传，字段名为 `file`，需要工作项附件读写权限；返回附件 ID、名称和大小等信息，图片还能获得用于描述的嵌入片段或永久代理路径。临时下载 URL 有有效期，不能作为长期证据身份。实现时由 HTTP 库生成 multipart boundary，不照抄示例中与 multipart 不符的 JSON Content-Type。见 [附件上传 API](https://help.aliyun.com/zh/yunxiao/developer-reference/createworkkitemattachment)。

**截图：按 PNG/JPEG 附件实现，上传后可使用返回的图片嵌入信息。视频：按 MP4 文件附件实现，不能将视频 URL 套进图片嵌入语法。** 官方上传 API 页面未列明文件类型白名单和单文件大小上限；官方通用文件说明列出了 MP4 预览，但项目文件、任务评论和知识库入口的规则不同，不能作为该 API 的当前限制承诺。参考 [上传格式和预览](https://help.aliyun.com/zh/yunxiao/user-guide/upload-format-and-preview)。

因此第一阶段必须验证指定组织的 PNG、JPEG、MP4 和 ZIP：上传、附件列表回读、下载内容哈希、云效页面显示。MP4 在线播放另测；能下载但不能内嵌播放时，客户端明确展示“视频附件可下载”，仍满足视频上传功能。

客户端可以设置自己的体积提醒阈值，例如超过 50MB 提示裁剪或压缩；这不是云效上限。实际限制在契约测试后写入可配置参数，服务端拒绝要呈现具体原因，不能预先承诺 200MB 或 1GB。若当前组织拒绝 MP4，列为阻塞并联系确认或调整官方支持路径，不能只写一个外部链接就宣称视频上传已完成。

## 7 证据包和 AI 交接格式

### 7.1 一份不可变证据包

每个问题导出一份 ZIP，同时保留本地可读报告与机器清单。证据包打包后记录 SHA256，不能为了补写云效 ID 而重新生成不同内容却沿用旧哈希。提交回执单独保存。

```text
<evidence-id>/
  report.md               人可读报告
  manifest.json           构建、事件、采集来源及证据状态
  device.json             设备快照
  app.json                应用快照
  logs/                   经确认上传的日志与关键片段
  media/                  截图、视频，按选项决定是否放入 ZIP
  cloud-config.json       有效云控记录及来源
  collection-errors.json  失败项、覆盖缺口及补充情况
```

截图和视频独立上传便于云效查看。默认 ZIP 不重复包含已独立上传的大视频，manifest 记录媒体文件名、大小、SHA256 和本地证据关联；需要离线完整交接时可导出含媒体的完整包。

### 7.2 清单契约

manifest 至少包括以下字段，实施时建立 JSON Schema 并支持 schemaVersion 升级：

| 分组         | 必要内容                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| 标识         | schemaVersion、evidenceId、sessionId、客户端版本、创建时间                                              |
| 范围         | organizationId、projectId、businessProfile、真实 iteration/version/custom scope，可选 Multica 父任务 ID |
| 构建         | 固定 buildUrl、buildNumber、job、包/渠道、混淆/加固状态、Git commit 可取得值、构建参数、身份核对状态    |
| 安装产物     | versionName、versionCode、包名、实际安装 APK 或 split 集合的可取得指纹及来源                            |
| 原始 CI 产物 | APK/AAB 的相对产物路径、类型、可取得 SHA256；与安装产物分开记录                                         |
| 问题         | 类型、标题、前置条件、顺序步骤、预期/实际、频率、事件时间、是否事后补采                                 |
| 设备         | 设备与应用快照，敏感标识使用当地别名或摘要                                                              |
| 云控         | 适用性、实际值、来源、观察/拉取/激活时间、覆盖项                                                        |
| 采集结果     | 每项 collected/failed/manual/not_applicable，采集时间、失败原因、人工来源                               |
| 文件         | 相对路径、MIME、大小、SHA256、证据角色、原始或衍生关系                                                  |
| 缺口         | 日志时间覆盖、断线间隔、未取得堆栈/符号等质量缺口                                                       |

JSON 中没有取得的可选值为 null 并有状态，不能用虚构 ID 或“已验证”填充。云效正文中使用可读的固定段落，附 evidenceId 和 schemaVersion，便于 Multica/AI 定位对应证据。

### 7.3 云效描述模板

生成顺序为：问题概述、前置条件、复现步骤、预期结果、实际结果、复现频率、问题时间、应用与设备、Jenkins 固定构建、有效云控、证据和采集缺口。复现步骤采用有序列表，日志全文作为附件，正文只放关键片段和路径。

正文中的“客户端证据”段落由客户端管理，保存 evidenceId、包哈希及附件关联。上传完成前注明证据待补，全部必需附件回读后再更新为 complete。其他正文由用户管理；补传时先读取最新描述，发现用户修改则合并管理段落或提示冲突，不能覆盖后续人工内容。

AI 处理时先验证范围、构建和 mapping 身份，再读日志与媒体。当前已有 android-obfuscated-crash-triage 和 video-keyframe-contact-sheet 能力可复用；客户端不内置自动诊断结论，也不把“采集成功”写成“问题原因已定位”。

## 8 可靠提交和错误恢复

云效创建缺陷与附件上传分成多次请求，不能承诺一个跨接口原子事务。客户端采用持久状态机：

```text
draft → ready → creating → created → uploading → finalizing → submitted
                     ↘ create_unknown
                                  uploading/finalizing → partial
```

1. 校验草稿，固定证据快照与 evidenceId，先持久保存创建意图。
2. 创建缺陷，收到响应后立即事务保存真实 workitemId。初始描述带唯一证据标记和“附件上传中”。
3. 上传每个必需附件，保存附件 ID，并读取附件列表核对。附件文件名带证据标记和哈希摘要，支持恢复核对。
4. 补全描述中的证据段落，回读缺陷和附件。只有全部必需材料已确认并且最终描述成功后，才显示“提交完成”。
5. 保存独立 receipt.json：组织、项目、workitemId、缺陷编号/链接、附件 ID、证据包 SHA256、提交时间和完成状态。

恢复规则：

- 双击提交与同一草稿并发提交被本地锁阻止。
- 创建请求超时但可能已成功，状态为 create_unknown；先根据该项目内可支持的查询条件和提交时间窗口读取候选，再核对详情中的唯一证据标记。未查清前不重新 POST 创建。
- 查询不完整、索引尚未更新或没有找到候选，不等于确认未创建。仍不确定时让用户在云效确认或提供已创建链接。
- 已知 workitemId 的附件失败，只补传失败附件，绝不重新创建 Bug；客户端与云效描述尽可能显示“缺陷已创建，证据未齐”。
- 附件上传响应丢失时读取列表核对；仅靠同名同大小不能证明内容一致，必要时下载比对哈希。确认不清时不盲目重复上传。
- 401 要求重新授权；403 给出项目或 API 权限检查入口；字段校验失败回到对应控件；限流与可安全重试的只读请求采用有限退避。
- 网络不可用保留草稿和证据，不伪造成功。应用退出或崩溃后恢复到实际已确认阶段。用户放弃部分提交时保留真实缺陷身份，默认不自动删除远端记录。

## 9 Jenkins 与混淆包身份

### 9.1 首版必需

要求填写固定构建号链接。可从合法 URL 自动解析 job 与构建号，但必须保留原链接和用户确认。允许测试人员粘贴 Jenkins 构建清单或选择本地下载的产物；没有 Jenkins API 授权时仍可提交满足其他必填信息的缺陷，身份状态标记 manual_confirmed。

已完成可信比对则标记 verified；取得相互矛盾证据则 conflict 并阻止提交。仅包名和版本相同、用户口头确认或文件名相似，不能宣称 mapping 与安装包已精确匹配。

### 9.2 CI 增强

建议 Jenkins 每个构建归档 build-manifest.json、实际 APK/AAB、最终 mapping，以及适用的 UltimateGuard diagnostics、组件和资源映射；native 问题额外保留同构建符号。manifest 包含实际 Git revision、分支、flavor/渠道、版本、关键参数、构建号、产物相对路径和显式 SHA256。归档与保留策略参考 [Jenkins archiveArtifacts](https://www.jenkins.io/doc/pipeline/steps/core/#archiveartifacts-archive-the-artifacts)。

客户端通过固定构建的只读 API 或导入清单补齐，Jenkins 凭据与云效 Token 分开管理，绝不把云效令牌发送给 Jenkins。构建元数据读取参考 [Jenkins Remote Access API](https://www.jenkins.io/doc/book/using/remote-access-api/)。

AAB 和安装后的 APK 不是同一个文件，不能直接比较两者 SHA256。AAB 转 APK 或 split 安装要记录转换工具、源 AAB、签名和安装输出之间的派生关系；最可靠的是测试会话绑定工具已安装的具体产物。仅版本号不足以构建这条关系。

映射还原由开发侧或已有 Skill 执行，依据同构建最终 mapping；R8 Retrace 用映射恢复混淆堆栈，见 [R8 Retrace 文档](https://developer.android.com/tools/retrace)。CI 增强尚未完成时照实标记缺口，不阻塞基础客户端研发。

## 10 与现有 Multica 流程衔接

```text
测试人员连接真机并收集证据
    → 人工预览和提交云效 Bug
    → 获得真实缺陷链接和证据回执
    → 在 Multica 点击启动bug修复并提供链接
    → 核对项目、方向、版本范围、修复分支和状态映射
    → 开发标处理中，修复并验证，提交 QA 可构建代码，标已解决
    → 测试人员重新打包复测
    → 测试关闭或重新打开原 Bug，并补充新的构建和证据
```

首版提供“复制缺陷链接”和“复制修复任务输入”，由使用者启动现有入口。修复输入包含业务方向、云效链接、版本范围、Jenkins 构建链接、evidenceId 和可选已有父任务。

后续可以接云效事件或 Multica 任务通知，但必须支持去重并等附件 complete 后再派发，不能因为创建了缺陷便默认授权 AI 修改代码。现有巡检仍暂停，独立修复自动巡检也没有因此完成验收。

客户端二期可提供“给已有 Bug 添加复测证据”，保留原始材料并追加新的测试构建；关闭和重新打开仍由 QA 明确选择并使用真实项目状态。全部 Bug 关闭仍不替代整个版本 QA 通过，也不自动触发生产包。

## 11 数据保存与附件操作

这些规则直接落在用户可见的预览与保存行为中：

- Token、授权请求头、Jenkins 凭据和登录信息不写入草稿、诊断日志、ZIP、云效正文、截图或 AI 输入。
- 会话目录只保存采集所需数据；报告对序列号使用设备别名或摘要，不采集 IMEI、通讯录等无关信息。
- 日志和系统报告可能带账号、路径或网络信息。提供上传预览及脱敏，默认上传经确认的材料；原始副本保留本地，单独允许用户选择上传，不以“已脱敏”保证消除了全部敏感信息。
- 附件校验文件存在、非空、实际格式、大小和哈希；图片和视频本地预览。用户删除附件只影响当前草稿，不自动删除远端已提交证据。
- 原图或原视频与裁剪/压缩后的文件分别记录哈希，保留衍生关系；不静默改变用于定位的画面或时间线。
- 配置本地保留策略并提供清理入口；未提交草稿和证据上传未完成的材料不能静默清理。默认期限在试用阶段根据团队需要确定。
- 长时采集有容量和剩余磁盘提示；只停止自己启动的子进程，避免影响 Android Studio 或其他 ADB 使用者。

## 12 分阶段实施任务

按依赖推进，每个阶段交付可运行结果，不先做完整界面再验证云效 API。以下工时为单人参考，不是承诺；联调账号、测试设备和企业签名准备影响时间。

| 阶段          | 内容                                                                                | 预计投入 | 验收与交付                                                   |
| ------------- | ----------------------------------------------------------------------------------- | -------- | ------------------------------------------------------------ |
| P0 接口契约   | 确认平台、验收项目；个人 PAT；Bug 类型与字段；PNG/JPEG/MP4/ZIP 上传及下载；实际限制 | 1至2天   | 小型联调程序、接口契约记录；真实视频通过，明确权限和默认状态 |
| P1 本地采集   | ADB 检测、设备选择、快照、持续日志、标记、截图、草稿和本地证据导出                  | 2至3天   | 真机连断、多设备、进程重启验证；本地报告可供开发读懂         |
| P2 提交闭环   | 动态字段表单、必填校验、附件预览、创建/上传/回读、状态恢复、凭据保存                | 3至4天   | 缺项零写入；截图、视频和证据包提交成功；失败不重复创建       |
| P3 桌面发布   | 两平台安装包、无开发环境安装、ADB 引导、Token 失效提示、试用修正                    | 1至2天   | 干净用户环境验收、测试操作手册、已知限制、发布产物           |
| P4 工作流增强 | Jenkins 清单归档与只读解析、设备安装身份、应用云控导出、复测追加、Multica 通知      | 另排     | 逐项独立验收；不挡首版完整 Bug 提交                          |

P0 的写入联调使用用户指定的测试项目或明确批准的测试缺陷，记录操作和清理方式；不要把现有已关闭业务 Bug 当试验对象。P0 不通过视频上传时先解决阻塞，不降低用户第5项要求。

### 12.1 实施开始前需要确认

1. 测试团队电脑系统与需要发布的 CPU 架构；若无新要求，按 Windows x64 和 macOS 规划。
2. 创建真实联调缺陷的项目或范围、可选负责人；所需个人 Token 在应用或本机安全输入，不发到聊天。
3. 云效项目的 Bug 类型、必填字段、版本/迭代的实际用法；由 API 读取后让用户确认映射。
4. 首版云控证据从哪个应用调试页面、日志或导出文件取得；若当前没有可信入口，为相关问题明确人工填写办法。
5. 当前 Jenkins 是否已归档 mapping 和构建清单，以及企业安装包签名与分发方式；可以安排在增强与发布阶段完成。

前四项影响产品验收；其中未确认的部分可先用 mock 数据推进本地功能，不从旧版本或示例猜真实生产配置。

### 12.2 建议实现模块和验证重点

| 模块       | 交付内容                                             | 有意义的验证                                                  |
| ---------- | ---------------------------------------------------- | ------------------------------------------------------------- |
| 项目与凭据 | 配置导入、PAT 输入/记住/清除、元数据适配器           | 失效 Token、项目无权限、换用户、密文存储及日志无凭据          |
| ADB 采集   | 设备管理、固定参数执行、快照解析、日志轮转与错误记录 | 多设备不串采、厂商输出差异、断线、应用重启、磁盘不足          |
| 表单校验   | 基础/条件/云效动态规则、来源与错误提示               | 每类关键缺项都阻止创建；项目新增必填字段；无效选项            |
| 媒体与证据 | 文件导入、图片粘贴、设备截图、清单与 ZIP             | 非空与格式检测、哈希稳定、原始与派生关系、凭据不进包          |
| 云效提交   | 创建、multipart 上传、回读、有限恢复                 | 写入超时、已创建附件失败、退出恢复、重复点击、用户编辑描述    |
| 发布       | 安装包、ADB 引导和操作文档                           | 两个目标系统真实启动与 USB 采集，不以本机开发启动代替发布验证 |

## 13 验收用例

1. 新用户没有 Token，进入授权向导；PAT 输入隐藏，可选本次使用。未授权仍可保存本地草稿，但不能向云效提交。
2. 保存 Token 后重开客户端可恢复；失效或撤销时要求重新填写，原草稿和证据保留。搜索应用日志、草稿与证据包，确认没有实际 Token。
3. 连接两台真机，选择其中一台后截图、日志、包信息均来自该设备；断线不自动切到另一台。
4. 测试进程崩溃后重启，日志仍包含重启前后及系统相关记录；缺口准确显示。
5. 每个必填项逐一清空，界面与主进程均拒绝提交，网络创建调用为零；自动采集失败的关键项必须人工补齐。
6. 云效新增一个项目必填字段，客户端读取后要求填写；未支持格式给出明确阻塞，不静默省略。
7. job 首页和动态 lastBuild 链接被拒绝；固定构建 URL 可用。设备身份与可信构建清单冲突时阻止提交。
8. 上传一张 PNG、一张 JPEG、一个 MP4 和一个 ZIP，云效附件列表有真实 ID，下载哈希匹配；截图描述可见，MP4 播放或下载行为如实记录。
9. 创建后模拟附件失败，显示“已创建，证据未齐”；恢复后补传到同一 Bug，最终只有一条缺陷。
10. 模拟创建响应丢失和附件响应丢失，进入核对状态，未确认前不重复写入；应用退出恢复后保留同样判断。
11. 接口查询多页、同名版本和同名成员，选择及 ID 均正确；不会漏掉第二页数据。
12. 与云控相关的问题未填有效值或来源不能提交；不适用需原因。事后后台值不会被自动标为设备当时值。
13. 本地 ZIP 的报告、manifest、时间、文件哈希和采集状态一致；回执另存，包内容不因上传过程改变。
14. 开发通过真实缺陷链接取得完整证据，用对应 Jenkins 构建补充 mapping 后可进入现有混淆定位和修复流程；身份不符时停止精确定位。
15. 在目标 macOS 和 Windows 上安装发布产物、连接 USB 真机并完成一次提交；其中一个平台未验证就明确列为未验收。

## 15 给后续实施会话的启动指令

读取本计划，实施 Android Bug 提交桌面客户端。先确认目标发布平台和独立源码目录，完成 P0 官方 API 契约验证，再推进本地采集和桌面提交闭环。复用已有结论，必须支持真机 USB、混淆测试包、个人 PAT、严格必填校验、截图和 MP4 文件附件。不要读取或共享现有协调员 Token；真实云效写入仅在明确指定的验收项目或测试缺陷中进行。先通过本地和 mock 验证，再用安装包做真机与云效验收。每阶段报告已经运行通过的能力、尚未验证的部分和下一阶段依赖。

实施交付包括：源码与依赖锁定、模块化测试、目标平台安装包、项目配置样例、证据 manifest Schema、接口契约与媒体限制记录、测试人员操作说明、实际验收报告及已知限制。以第13节用例判断完成，不以界面截图或编译成功代替真实提交闭环。
