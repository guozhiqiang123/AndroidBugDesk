# 测试人员操作说明（0.1.0 UI 修订）

1. 打开客户端会在线校验已保存的个人访问令牌。没有令牌、失效或无法完成校验时进入登录界面。输入自己的令牌，点击“确定”；校验成功进入主界面，失败保留登录界面。默认仅本次使用，勾选“记住登录”只使用系统安全存储；不可用时选择仅本次使用。
2. 主界面只有“新建提交”和“历史提交”。顶部连接 USB 设备，刷新列表并明确选择设备；未检测到 ADB 时选择官方 Platform Tools 中的 adb。
3. 从 API 返回的组织、项目列表选择目标。首次使用不预置示例项目。令牌有效后，项目权限不足或网络失败会留在主界面供重试；运行中确认令牌失效则返回登录。
4. 补充标题、问题描述、负责人、迭代、版本及项目返回的关键字段。验证者、优先级、严重程度、参与者、抄送、标签等按实际字段配置显示。下拉值来自 API；无选项会提示，不猜取值。新增未支持的必填字段会阻止提交。
5. 每次下拉选择自动记忆，下一份新草稿按账号、组织、项目、Bug 类型恢复。删除的选项不恢复。组织和项目按账号记忆。标题、描述和任意文本不作为选择偏好保存。
6. 填写包名、业务方向及固定 Jenkins 构建 URL，开始采集。复现后记录问题并截图，继续约 30 秒后固定日志。自动失败项人工补齐并注明来源，明确日志真实覆盖时间。此 UI 评审分支尚未合入独立采集增强任务。
7. 导入并确认 PNG/JPEG、MP4、日志、系统报告 ZIP 和所需样例。补齐步骤、结果、频率、应用及设备信息、设备当时生效的云控。保存草稿，清空待补项，预览核对目标项目、固定构建、描述和附件。获得本次真实写入授权后才进行真实提交验收。
8. “历史提交”保留本机持久回执及恢复入口，另分页读取当前账号在当前项目创建的云效 Bug。权限不足或失败明确显示，不当作零历史。创建结果待核对时必须核对原工作项；已创建但证据未齐时恢复原工作项，不能重复创建。
9. 旧草稿、回执和不可变证据包保留。旧版没有账号/项目绑定的未提交草稿必须新建目标项目草稿并补入需要的信息后再提交，避免投递到错误项目。

不要在聊天、截图、日志或草稿中填写令牌。退出登录停止采集并清除授权。登录校验需要组织管理「用户」只读权限，组织、项目、成员、字段及历史还需对应读取权限；仅工作项读写可能不足。当前真实写入仍未授权，各平台安装、安全存储及完整 USB/媒体提交仍待验收。
