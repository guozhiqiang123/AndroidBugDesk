# Android Bug Desk 使用说明

1. 使用“授权登录”或个人 PAT 登录云效。只有勾选“记住登录”时才会使用系统安全存储保存凭据；退出登录会清除当前授权。
2. 在“设置”中选择云效组织，刷新项目列表，为需要在主页使用的项目填写 Android 包名并勾选启用，然后保存。主页、设备读取、补采和提交都以该包名映射为准。
3. 在“新建提交”选择项目和草稿，填写必填的问题标题和问题表现；Jenkins 包地址、期望表现、复现步骤和复现条件按实际情况选填，再完成云效返回的负责人、迭代、优先级等字段。四个问题描述框支持 Markdown 和单行格式工具栏；代码块可直接输入围栏 Markdown。需要插图时，从系统文件管理器复制一张 PNG/JPEG，在目标描述框中按 macOS `Command+V` 或 Windows/Linux `Ctrl+V` 即可插入并预览，无需先导入附件；图片右上角的关闭图标可将该图片从当前描述中移除。崩溃、ANR、多语言乱码等问题建议填写 Jenkins 包地址，便于开发快速定位对应构建。参与者和抄送默认不选。
4. 在“证据附件”中选择目标设备。未检测到 ADB 时，点击“选择 ADB 路径”选择 Android SDK Platform Tools 中的 adb；点击“刷新设备”重新读取设备列表。
5. “设备环境快照”采集当前设备和目标应用的只读环境摘要并保存为附件。“补采证据”按问题类型选择日志、截图、界面层级、崩溃记录、性能或网络等项目；已完成项目默认不重复勾选。“导入附件”用于添加用户已有的图片、视频、日志、ZIP 或样例文件。
6. 附件不是必填项。点击附件预览时由系统应用打开；macOS 图片使用系统图片预览，ZIP 使用 Quick Look。设备环境快照和补采证据产生的受管附件会随草稿删除，用户导入的原文件和已导出的本地证据不受影响。
7. “提交前核对”常驻在新建提交窗口底部，不随正文滚动，并会把错误定位到对应输入项。通过核对后可保存草稿、导出本地证据或打开提交预览弹窗；在弹窗中核对内容后，可直接点击“提交 Bug”。没有明确真实写入授权时只进行本地和模拟验证。
8. “历史提交”分为本机记录和云效历史 Bug 两个 Tab，滚动列表时 Tab 固定在内容区顶部。筛选条件绑定主页当前项目；本机记录保留恢复入口，云效历史只读取当前账号在当前项目创建的 Bug。
9. 需要排查客户端卡顿、崩溃或 ADB 超时时，可在“设置 → 开发者选项”开启调试。开启后，“证据附件”会显示“软件证据”；点击后生成一份受限、脱敏的诊断 ZIP 并加入当前草稿。该按钮不要求连接设备。同一草稿再次生成会替换旧软件证据。
10. 应用启动时会静默检查 GitHub Release。发现新版本后可在提示弹窗或“设置 → 检查更新”中点击“立马更新”；下载过程显示阶段、进度和速度。客户端会读取环境变量以及 Windows/macOS 常见手动系统代理设置；连续 45 秒没有下载进展会停止并保留当前版本，可检查系统代理后重试或打开 Release 页面手动下载。使用 PAC/WPAD 自动代理的 Windows 环境仍建议先验证，遇到问题时开启调试并生成“软件证据”。

调试日志不会无限增长：基础日志最多约 4 MB，详细日志最多约 20 MB，保留 7 天；失败的整机报告诊断最多保留 3 份、合计约 12 MB；单个软件证据 ZIP 最大 25 MB。关闭调试后停止写入详细日志，基础启动、崩溃和主线程异常仍保留在小容量轮转日志中。

选择设备后，客户端会持续记录当前项目目标应用最近一次位于前台的 Activity，并填写到“Bug所在页面（选填）”。切到桌面或其他应用不会覆盖该值；因此应用崩溃返回 Launcher 后仍保留崩溃前最后一次目标应用页面。页面下方会显示采集时间和来源。需要修正时可以直接填写或清空，人工结果不会再被自动读取覆盖。

草稿和证据数据不再包含渠道、业务方向、人工补充信息来源、旧固定构建字段、构建状态或构建清单。用户填写的 Jenkins 包地址会保存到草稿，并进入提交预览、云效描述和本地证据报告。设备型号、Android 版本、内存、分辨率、应用包名和版本仍属于设备环境快照，也会进入本地证据报告。旧开发草稿中如果仍包含已删除字段，需要新建草稿。

不要在聊天、截图、日志或草稿中填写 PAT、访问令牌或刷新令牌。应用只把凭据用于云效授权请求，不会写入草稿、报告或证据包。
