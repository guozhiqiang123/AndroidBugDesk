# 测试人员操作说明（0.1.0）

1. 打开客户端，“授权与项目”填写自己的 PAT。默认仅本次使用；如系统安全存储可用，可选择保存。离线时也可创建草稿、导入证据和导出 ZIP。
2. 导入项目 JSON，或使用照片恢复PR配置。点击读取项目，选择正确的 Bug 类型并读取对应字段。项目读取成功只验证读取能力。
3. 安装官方 Platform Tools，USB 连接真机并在手机允许调试。刷新设备，明确选择目标；填写包名、业务方向及固定 Jenkins 构建 URL，然后开始采集。
4. 复现后点击“记录问题并截图”。电脑时间为原始标记，设备时钟估计保存在本地快照中。继续约 30 秒，点击“固定会话日志”。每次固定生成新的本地副本；初始缓冲区日志覆盖起止未自动解析，需要人工填写。
5. 补充应用、设备、前置条件、有序步骤、结果、频率及设备实际有效云控。自动失败项需注明人工来源；云控不适用需具体功能依据。
6. 导入 PNG/JPEG、MP4、UTF-8 日志、系统报告 ZIP 或需要的样例。逐份查看并勾选“确认上传”。日志填写真实覆盖时间；只有已确认材料进入导出与提交。上传前人工核查账号、路径、网络和业务信息。
7. 保存草稿。待补清单清空后进入预览，核对项目、负责人、范围、构建、描述和附件，再勾选确认并点击提交。
8. “提交记录”显示实际阶段。结果待核对时先读取云效候选，或填写云效工作项 ID 核对；不能重新创建。已创建但证据未齐时点击核对并恢复，只处理原工作项。
9. API 未返回可确认的真实缺陷链接时显示工作项 ID，不伪造链接。真实链接契约还需验收；复制修复输入会注明缺口。

不要在聊天、截图、日志或草稿里放 Token。本机复制附件保留原始内容；当前不提供“已完整脱敏”保证。清理策略、脱敏副本、文件拖放、图片粘贴和一键 bugreport 为下一批任务。
