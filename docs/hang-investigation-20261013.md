# macOS 无响应跟踪（2026-10-13）

## 现场结论

- 安装版为 `0.2.1`，进程自 2026-10-12 19:07 起持续运行，发生无响应时 CPU 为 0%，没有应用所属的 ADB 子进程。
- 系统没有生成崩溃、卡死或 Spin 诊断报告，旧版也没有应用级落盘日志。
- 两次独立进程采样分别持续 8 秒和 5 秒，主线程在全部样本中都停在 WebKit `WebURLSchemeHandlerCocoa::platformStartTask`，随后进入 Wry 自定义协议任务表的互斥锁等待。
- 一个 Tokio 后台线程同时处于互斥锁等待，其余运行时线程正常休眠。该状态是稳定死锁，不是短暂卡顿，也不是 ADB 忙循环。
- 设备在 03:28 后经历多轮 Sleep/DarkWake，并于 09:42 完整唤醒。休眠恢复与问题发生相关，但现有版本没有日志，无法证明休眠是唯一触发条件。
- 前端在设备选中且位于新建页面时每 1.5 秒发起一次完整 `bootstrap` IPC，上一轮未完成时仍会继续发起。后端前台页面观察器同时每秒执行一次 ADB 读取。休眠恢复时重叠 IPC 会持续经过 Wry 自定义协议，是当前最可信的触发链。

## 本轮处理

1. 采集并保留两份进程样本、系统电源事件和匹配安装包 UUID 的本地二进制信息。
2. 将前端采集结果同步改为串行执行，上一轮未完成时跳过；页面不可见时暂停，重新可见或获得焦点时立即同步；常规间隔调整为 3 秒。
3. 新增 `diagnostics/runtime.log`，达到 2 MiB 后轮转为 `runtime.log.1`。日志只记录固定运行事件，不记录令牌、设备序列号、项目或缺陷内容。
4. 新增主线程看门狗。后台每 30 秒向主线程投递一次探针，10 秒内未执行时写入无响应记录。
5. 记录应用启动、退出、设备读取、前台页面观察器启停及首次连续读取错误。
