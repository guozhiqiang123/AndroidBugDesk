# 自动更新网络与下载进度实施计划

## 背景与结论

当前更新检查和安装包下载都由 Rust `reqwest` 完成，不经过 WebView。项目关闭了 `reqwest` 默认功能，却没有重新启用 `system-proxy`，因此安装版通常只会读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 环境变量。Windows 从开始菜单启动时通常没有这些变量，无法读取“Internet 设置”中的手动代理；macOS 下载成功可能来自直连、TUN/VPN 或进程环境，不能证明应用已经使用系统代理。

当前安装包以单次 `response.bytes()` 读入内存，整个过程只显示固定文案，总超时 900 秒。GitHub API 可访问而资产 CDN 无法访问、代理未生效或下载停滞时，界面会长时间表现为“正在更新”。

## 目标

- 自动读取环境变量和常见的操作系统手动代理设置。
- 使用操作系统证书根，兼容企业代理安装到系统信任库的证书。
- 安装包分块写入临时文件，同时增量计算 SHA-256，不把完整安装包保留在内存。
- 更新弹窗显示连接、下载、校验和准备安装阶段，以及已下载大小、百分比和平均速度。
- 连续 45 秒没有收到安装包数据时终止本次下载并给出可操作的错误；总请求仍保留 15 分钟硬上限。
- 运行日志记录代理能力、目标类别、阶段、耗时、字节数和失败种类，禁止记录代理地址、代理凭据、完整下载 URL或响应正文。

## 代理与证书策略

`reqwest` 启用 `system-proxy` 和 `rustls-tls-native-roots`：

- 环境变量代理继续优先，包括大小写两套 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 和 `NO_PROXY`。
- Windows 读取当前用户 `Internet Settings` 中启用的 `ProxyServer` 和 `ProxyOverride`。
- macOS 读取 SystemConfiguration 中启用的 HTTP/HTTPS 代理。
- Linux 继续使用环境变量代理。
- 只记录代理来源类别，例如 `environment` 或 `system-or-direct`，不读取和落盘代理地址。

`system-proxy` 不完整解析 Windows PAC 脚本、WPAD 或所有协议分离格式。本轮先覆盖常见手动系统代理；若用户环境使用 PAC/自动检测，后续基于软件证据决定是否接入 Windows 原生代理解析 API。不得静默回退到跳过 TLS 校验。

## 下载状态与超时

后端通过 Tauri IPC Channel 回传固定结构：

- `connecting`：准备连接 GitHub 安装包地址；
- `downloading`：已下载字节、总字节、整数百分比和平均每秒字节数；
- `verifying`：字节数完成，正在核对大小和 SHA-256；
- `preparing`：校验通过，正在启动平台安装程序。

安装包先写入同目录唯一 `.download` 临时文件。每次读取数据块都更新 SHA-256 和大小，超过 Release 声明大小或 512 MiB 上限立即停止。连续 45 秒没有新数据返回“下载长时间没有进展”，删除临时文件并保持当前应用运行。成功后校验实际大小和 GitHub Release SHA-256，再原子改名为最终安装包。

界面只使用后端进度值，不按时间估算虚假百分比。总大小未知时显示已下载大小和速度，不显示百分比。错误弹窗保留“打开 Release 页面”入口。

## 诊断与隐私

基础日志记录更新任务开始、完成或失败以及总耗时；详细日志记录阶段变化和节流后的字节进度。允许字段仅包括：平台、架构、代理来源类别、阶段、下载字节、声明字节、百分比、速度、HTTP 状态类别、错误类别和耗时。

禁止记录：代理服务器主机或端口、用户名、密码、认证请求头、Cookie、下载 URL、重定向 URL、响应正文和本地用户目录。软件证据沿用现有日志轮转和脱敏上限，不另建无限增长的更新日志。

## 实施顺序

1. 调整 `reqwest` 功能，启用系统代理与系统证书根。
2. 建立更新进度结构、IPC Channel 和脱敏诊断事件。
3. 将安装包下载改为分块临时文件、增量哈希、大小上限和 45 秒停滞超时。
4. 更新弹窗显示阶段、进度条、字节数和速度。
5. 更新浏览器模拟、单元测试、用户指南、实施记录和验收清单。

## 验收标准

- 依赖树包含 `reqwest/system-proxy` 和 `reqwest/rustls-tls-native-roots`，不再使用 WebPKI 固定根作为更新请求的唯一信任来源。
- 模拟分块下载可以写出与声明大小和 SHA-256 一致的文件，且进度单调递增。
- 模拟无数据、超大响应、长度不符和哈希不符均失败并删除 `.download` 文件。
- 前端依次显示连接、下载进度、校验和准备安装；失败后可以关闭或打开 Release 页面。
- 诊断测试确认代理 URL、凭据和下载 URL 不进入日志字段。
- TypeScript、前端测试和生产构建、Rust 测试、Rust 格式、严格 Clippy、受影响的浏览器更新场景及差异检查全部通过。
- Windows 真机仍需分别使用手动系统代理和 PAC/自动检测环境验收；PAC 未经真机验证前保持显式边界。
